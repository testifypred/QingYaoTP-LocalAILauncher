# QingYaoTP AILauncher（本地 AI）· 技术版

> 这是**技术版**：构建 / 打包 / 探针 / 目录结构与踩坑。面向最终用户的说明见 [README.md](README.md)（客户端版，也是首启弹窗里显示的那份）。

> 一台 Windows 机器上的**纯本地 AI 工作台**：模型跑在本机（llama.cpp），界面是本地网页，数据不出门，能离线用、能改、能扩。
> QingYaoTP = QingYaoTestifypred；图标是**不定积分 ∫ + AI**。

---

## 这是什么

不是「又一个聊天客户端」。它要解决的是**第一次把本地大模型跑起来这件事**：首启自动体检硬件、推荐能跑的模型、一键下载、30 秒内看到第一句回答；跑起来之后，工具调用、联网、看图、代码工作区、会话管理、调试工具都在同一个窗口里。

## 5 分钟跑起来（便携包）

1. 解压到**可写目录**，例如 `C:\QingYaoTP AILauncher`。**不要**放 `Program Files`，也不要套两层目录。
2. 双击 `QingYaoTP AILauncher.exe`。
3. 缺 VC++ 运行库时它会自己弹窗引导安装（安装包已随包）。
4. 首次启动会自动：体检硬件 → 嗅探本机已有的 `.gguf` → 没有就引导下载一个极小的模型（约 470MB）→ 下载完自动加载并发第一句。
5. 模型也可以自己放：把 `.gguf` 丢进 `<安装目录>\models\`（`config.ini` 的 `modelDir` 留空即用这个目录）。

> 首次启动会自动显示**本文件**；之后想再看：设置 → 关于 →「使用说明…」。

## 视觉增强包（可选）

看图要一个独立的小程序（llama.cpp 的 `llama-server` + DLL，解压后 **101.1MB / 53 个文件**）。它**不随主包**：主包因此从 158.5MB 降到 **约 122MB**，不看图的人不用为它付流量。

装它（约 37MB 的 zip）：

1. **设置 → 视觉** → 顶部「视觉增强包」卡片 → **安装视觉增强包…** → 选中下载来的 `QingYaoTP-AILauncher-v1.6.0-vision-pack.zip`；
2. 或者把 zip 和主包放在同一个目录（比如 `dist\`，或安装目录下的 `vision-pack\`）再打开这一页，卡片里会列出「检测到本地增强包：…」→ 点**一键安装**；
3. 装完**立刻可用，不用重启**；状态行显示「已安装 v1.6.0 · 53 个文件 / 101.1 MB」，来源写「包安装」。

| 情况 | 能不能看图 | 说明 |
|---|---|---|
| 没装增强包 | 不能 | 文本对话、工具、联网、代码工作区全照常；点图片按钮只弹提示「去 设置 → 视觉 装」 |
| 装了增强包 | 能 | 来源「包安装」，可随时**卸载**（同一张卡片，释放约 101MB） |
| 从 ≤v1.5.1 升上来的机器 | 能 | `app\llama\` 里的老文件照旧可用，来源显示「老版本自带」，也可以卸 |
| 源码开发态 | 能 | 直接用仓库 `tools\llama.cpp\`（来源「开发目录」）——那是仓库资产，**不能**在界面里卸 |

> 「检测到本地增强包」只认文件名里带 `vision-pack` 的 `.zip`。安装/卸载都会**先停掉正在跑的看图进程**（Windows 上换 exe 会被占用），正在看图时会提示稍后再试。

## 终端与代码审查（v1.7.0 / v1.8.0）

### 终端 TUI

顶栏「终端」或 `localai tui`（也可以 `node server\localai-tui.mjs`）：

- 头部常显 **tui 2.0.0 + 主程序版本**（`/version`、`--version` 也能查，排障第一条信息）。
- 模型回答按 **Markdown 降级渲染**：粗体 / 斜体 / 行内代码 / 代码块（带语言标签）/ 标题（▌）/ 列表（•）/ 引用 / 链接各有颜色；**LaTeX 折成 Unicode 近似**（`\frac{a}{b}` → `(a)/(b)`、`\alpha` → α、`x^2` → x²、`\le` → ≤）并染洋红。流式靠 SSE 直连 + 16ms 合帧（`--bench`：整帧 0.06ms、Markdown 6600 字 1.30ms）。
- 空输入按 `/` 打开**能力面板**：12 条命令 + 当前全部软件工具（`/tool 名字`），`↑↓`/`Tab` 选择、`Enter` 执行、`Esc` 收起；工具缺必填参数会先填进输入框，执行完自动回对话界面。
- 输入区是**线框**（`╭ ╮ ╰ ╯`）+ 反显**光标块**（NO_COLOR 下是 `▏`），长输入自动多行、窗口跟着光标滚。
- 生成中底边框显示 **`/ - \ |` 旋转 + 随机原创颜文字 + 已用秒数**；`Ctrl+C` 中断。
- 命令提示：`/` 开头一行灰字补全 + 下方提示条（最多 6 行）；`Tab` 补全 / 连按切换候选、`→` 接受、`Esc` 收起，半截命令直接回车也会补成首个候选。
- `/help` 命令总览；`/tools` 列全部软件工具（`*` = 必填参数）；`/tool` 直接调用，例如：

```text
/tool get_current_time
/tool calculate expression="12*12+1"
/tool web_search query="本地大模型 怎么部署" engine=baidu
/tool calculate --json '{"expression":"2**10"}'
```

  `key=value` 会自动认类型（数字 / true / false / null / 字符串），`--json` 直接给完整参数；结果 JSON 美化打印（过长自动截断），`result.error` 红字。管道 / 重定向（`--plain`）也能跑，方便脚本。
- 按键：`Ctrl+C` 中断生成（面板开着时先收起面板），再按一次退出；`↑↓` 历史、`PgUp/PgDn` 翻页。
- 一次性开关：`--version`（版本）、`--faces`（全部颜文字）、`--color` / `--no-color`（强制彩色 / 关闭颜色，环境里有 `NO_COLOR` 时用前者）、`--selftest`（61 项自检）、`--snapshot [--menu] [--gen]`（版面）、`--bench`（渲染耗时）、`--plain`（管道）。

### 主页面流式渲染（2026-11-22 输出优化）

- 生成中不再每 80ms 重建整段 `innerHTML` + 全量 KaTeX（6000 字单帧 14.3–16.8ms，O(n²)）；改成**按 Markdown 块增量渲染**：已闭合块只渲染一次（含公式），未闭合尾巴只做行内 Markdown，流结束整体再渲染一次（单帧 **0.37–0.48ms**）。
- 刷新从 `setTimeout(80ms)` 改成 `requestAnimationFrame`，滚动也合并到下一帧。
- 输入区上方新增**首字税提示**（工具开 ≈7s / 思考开 ≈15s / 都关 ≈1.5s）；Agent / 推理模式改为**一次性**，发完自动恢复，不再持久化。
- 设置 → 生成 新增**极简流式**：生成中只追加纯文本，结束后再套 Markdown（CPU 最省）。
- 工具说明瘦身：10 个工具描述 858 → ~400 字，工具模式下正文首字 **6.4–7.1s → 5.3–5.9s**。

### 代码审查工作流

顶栏「代码」→ 左侧文件列表 / 中间编辑器 / 右侧审查面板：

- **新建文件可选语言**：工具栏语言下拉（15 种）；名字不写扩展名会自动补（选 Python 输入 `main` → `main.py`）。
- **审查**：点「模型审查」→ 先**流式**显示「审查思路」，再出问题清单；问题行按严重度在代码里**高亮**，点问题卡片跳到对应行。第二阶段会显示实时秒数（「正在整理问题清单…」），觉得久就点同一个按钮——它会变成**「停止」**。
- **审查模型**：面板顶部的下拉，默认「本对话模型」，也可以选另一个模型专门审查（会先切模型；审查期间不能切别的）。**Phi-4-mini 已从下拉里隐藏**（v1.7.1 起；它在 Vulkan 上偶尔会把服务卡死，2026-11-15 实测），4B / 9B 都正常。
- **没问题时**：显示「✓ 这次没有发现问题」并给三条改进建议（「一键纠正」灰着，鼠标悬停会说明原因）；问题卡片下方还会显示该行**原文**（空行显示「（空行）」），行号已经校正到真正带代码的行。
- **一键纠正 / 单条更改**：一次改掉全部问题，或只改某一条；v1.9.2 起**纠正成功直接写回文件**（状态行「已写回文件」）；改动行用另一种颜色标出，状态行显示「已修改 N 处（新增 a / 删除 b）」。工具栏还有「保存并运行」。
- **发回对话**：把当前代码（附改动行摘要）包成代码块填进聊天输入框，**不自动发送**，可以再加几句话一起发。
- **高亮颜色**：设置 → 代码，四个取色器（错误 / 警告 / 提示 / 改动行）+ 恢复默认。
- 审查 / 纠正进行中**不要切模型**——会提示「代码审查/修正正在进行，等它结束再切换模型」（409）；这是防止原生层卡死的保护，不是 bug。

### 多文件 / 整工作区一起审查（v1.10.0）

文件列表每一行左边多了勾选框（表头有「全选」和「已选 N」），面板顶上两个入口：

- **审查选中**：审勾选的那几个文件；**审查工作区**：审 `workspace\code\` 下当前列表里的全部文件。
- **计划先行**：接口先算计划（`POST /api/code/review/multi/plan`，不需要模型）——一次最多 **8 个**、单文件 **6000 字符**、累计 **36000 字符**；超出/空文件/读不到的会在结果区列出**跳过原因**，不会静默丢。
- **逐文件串行审**（`POST /api/code/review/multi`，SSE）：每个文件独立小 sequence、两阶段（流式思路 → JSON 问题清单），单个文件失败只标红那张卡、不影响其余文件；审查中 `POST /api/load` 仍然 **409**（与单文件审查共用 `codeJobLocked` 同一把锁）。
- **跨文件总览**：两个及以上文件时，会拿各文件摘要与问题标题再做一轮，找「调用与实现不匹配 / 重复定义 / 约定不一致」这类跨文件问题，**不重复各文件内部已列的问题**。
- **结果交互**：每文件一张卡（点卡片头打开该文件并高亮该文件的问题）；问题卡点一条 = 打开文件 + 跳到该行；跨文件问题同样可跳。
- **导出**：`POST /api/code/review/export` 的 `kind:"multi"` → `<slug>-YYYYMMDD-HHmm.multi.review.md`（总览 / 逐文件结论 / 跨文件问题 / 跳过清单，只含结论不含代码正文）。

- 多文件模式**不参与**质询 / 他人复审 / 云端复审 / 三方对照（那些仍是单文件跑）；多文件的问题卡也没有「一键更改」。

### 二次验证（v1.8.0）：质询 / 他人复审 / 云端复审

单模型自审有盲区（模型看不出自己刚才漏了什么），所以审查面板旁边多了三种「复核」手段：

- **质询**：点「质询」输入你的质疑（例如「第 3 行不是 bug，因为这里是空列表的默认分支」），会把「代码 + 原审查结论 + 你的质疑」一起再喂回模型，让它**反驳或自证**——每条质疑给「成立 / 不成立 / 需验证」+ 依据 + 最小验证步骤，可以连着追问几轮（记录留在面板里）。
- **他人复审**：点「他人复审」换**另一个模型**独立再审一遍（下拉可指定；默认自动挑一个与当前不同的模型；只有一个模型时用同一模型、更高温度、对抗式提示词）。审完并列两栏，并给出判定：**一致** / **仅一方提出** / **互相矛盾**（「一方说没问题、另一方说有问题」也算矛盾），点条目能跳到对应代码行。
- **云端复审**（可选）：设置 → 代码 里填 OpenAI 兼容 API（baseURL / 模型 / API Key）。**Key 只存本机（`data\cloud-review.json`）、不进日志、不随交付包发出**；只接受 https（本机回环可用 http）。点「云端复审」**每次都会弹窗确认**「会把当前文件的代码（已脱敏）发到 <域名>」，确认才发；只发当前文件，发之前先把 `sk-…` 密钥、邮箱、本机绝对路径、内网 IP、长哈希替换成占位符，面板上会显示本次替换了几处。

## 从源码运行 / 自己打包

前置：**Windows 10 1809+ / 11**、**Node.js 24+**（要真 `.exe`，不是 npm 的 `.cmd` 垫片）、.NET Framework 4.x 自带的 `csc.exe`（编译启动器用，Windows 自带）。

```powershell
# 1) 装依赖
cd server
npm install

# 2) 开发态直接跑（默认监听 127.0.0.1:8099）
node app.mjs
#    浏览器打开 http://127.0.0.1:8099/

# 3) 打包成便携目录（产物：dist\QingYaoTP AILauncher）
powershell -NoProfile -ExecutionPolicy Bypass -File .\build-portable.ps1
#    换输出位置：-OutDir 'E:\build\dist\QingYaoTP AILauncher'
#    指定随包 node：-NodeExe 'C:\Program Files\nodejs\node.exe'

# 4) 打「视觉增强包」zip（产物：dist\QingYaoTP-AILauncher-v<版本>-vision-pack.zip）
powershell -NoProfile -ExecutionPolicy Bypass -File .\make-vision-pack.ps1

# 5) 打成对外交付的单文件 zip（产物：dist\QingYaoTP-AILauncher-v<版本>.zip）
powershell -NoProfile -ExecutionPolicy Bypass -File .\make-zip.ps1
```

- **不写死任何盘符**：脚本里的路径都由「脚本自身位置」推导，版本号由 `server\app.mjs` 的 `APP_VERSION` 解析——换台机器、换目录都能构建。
- **主包默认不带视觉**（v1.6.0 起）：`build-portable.ps1` 不打 `app\llama\`，`make-zip.ps1` 还会断言交付 zip 里没有 `app/llama/` 条目。要「离线一体化包」（目标机没法单独装增强包）就加 `-BundleVision`，恢复旧行为。
- **视觉增强包**由 `make-vision-pack.ps1` 从 `tools\llama.cpp` 打包（约 101MB 的 sidecar，不入库）：源目录默认 `tools\llama.cpp`，产物默认落在 `dist\`；缺 required 文件会直接 exit 1。
- **模型权重不入库**（GB 级），自己下或首启下载。

## 常见问题

| 问题 | 处理 |
|---|---|
| 双击没反应 / 一闪而过 | 先看 `logs\app.log`；缺 VC++ 运行库最常见；也可运行 `localai-debug.cmd`（服务没起来也能诊断） |
| 界面打开是白屏 | 端口被占（启动器会自动改口并写回 `config.ini`）；或被安全软件拦了本地回环 |
| 发图提示「视觉增强包未安装」 | 设置 → 视觉 → **安装视觉增强包…**（选 zip 或点「一键安装」，约 37MB，装完不用重启）；只看文字可以不管它 |
| 卸载视觉增强包失败 | 先把看图进程停掉（设置 → 视觉 →「停止」按钮，或等它闲置 300s 自动退出）；正在看图时安装/卸载都会被拒绝，等图看完再来 |
| 生成很慢 | 设置 → 显卡 看看有没有选到独显；上下文别开到 64K 以上；第一次提问要预填充，慢是正常的 |
| 代码审查要等挺久 | 正常：审查是两阶段（先流式给「审查思路」、再整理问题清单），4B 实测单文件约 30–50s、纠正约 10–15s；代码越短越快 |
| 多文件审查要等挺久 | 正常：多文件是**逐个文件串行**审（约 60–90s/个），一次最多 8 个；2 个小文件约 2–3 分钟，再加一轮跨文件总览 |
| 审查中提示「代码审查/修正正在进行，等它结束再切换模型」 | 正常保护：审查/纠正在跑时不能切模型（切了可能把服务卡死）。等它结束或按 Ctrl+C 中断后再切 |
| 质询 / 他人复审要等挺久 | 正常：每次都是一轮完整生成（4B 约 15–60s，换模型的复审更久，因为要先加载另一个模型） |
| 云端复审点不动 / 提示先配置 | 设置 → 代码 →「云端复审」填 baseURL（如 `https://api.openai.com/v1`）、模型名、API Key 并勾「启用」；只接受 https（本机回环可 http） |
| 云端复审会把我代码传出去吗 | 只有你**显式启用**并且**每次点确认**才会；只发当前文件、发前先脱敏（密钥/邮箱/本机路径/内网 IP/长哈希 → 占位符），面板会显示替换了几处 |
| 显存不够报错 | 换更小的量化（Q4_K_M）、模型或上下文档位；关掉看图（同一时刻只跑一个重模型） |
| 想换模型 | 顶栏「模型」菜单选一个即加载；行尾「删」可删（默认进回收站，可还原） |
| 开了「调用工具」后回答变慢 | 正常：工具说明要预填充（约 550 token），首字会从 1–2 秒变成 7–8 秒。**普通问答保持关着**，需要查时间/算数/读文件时再开，或从开场白点「Agent 模式」 |
| 数据在哪 | `<安装目录>\workspace\`（会话、代码、索引）与 `data\`（界面状态）；整个目录拷走就是完整备份 |
| 怎么卸载 | 直接删安装目录；没有注册表、没有系统服务、没有后台常驻（模型加载只在本进程内） |

## 数据与隐私

- 模型推理、会话、索引、检索**全部在本机**完成，默认只监听 `127.0.0.1`。
- 只有你主动开启「联网」时，模型才会把查询词发给搜索引擎并读取网页正文；本机地址与内网网段被拒绝。
- **云端复审（v1.8.0，可选，默认关闭）** 是唯一会把代码送出本机的功能：需要你填好并启用，而且**每次调用都要在弹窗里确认目标域名**；只发当前文件、发前脱敏；API Key 只存在本机 `data\cloud-review.json`，不写日志、不随交付包发出（打包脚本还会断言包里没有它）。
- 下载模型会连 ModelScope（或你给的自定义链接）。
- 诊断包导出是本地 zip，不会自动上传。
