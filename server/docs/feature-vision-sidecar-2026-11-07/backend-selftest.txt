〇、本轮修复（Lead 证据：单条视觉请求也会让 sidecar 崩）
  修复前：Vulkan 侧车（-ngl 99）每完成一次 mtmd 图像编码就 device lost：
    ggml_vulkan: device lost on Vulkan0 -> mtmd_batch_encode: ErrorDeviceLost -> sidecar 退出 code=3221226505 (0xC0000005)
  修复：
  1) sidecar 默认改 CPU 后端：-ngl 0；环境变量 VISION_NGL 可覆盖（默认 0，设 99 才上 GPU 对比）
  2) /v1/chat/completions 视觉转发加串行锁：FIFO 队列，同一时刻只允许一个请求进 sidecar，排队上限 180s
     （排队超时回 503「视觉请求排队超时（180s）」；排队期间也算有视觉请求，/api/load 会 409）
  3) 崩溃自愈：转发前检查 sidecar 进程存活 + /health；进程已退出/无响应 -> 自动重启；
     转发失败（非流式、或流式首块发出前）最多自动重启重试 1 次；仍失败回 502 并带 vision.log 路径。
     非预期退出在应用日志里明确写「视觉：sidecar 崩溃（code=...），下次转发会崩溃重启」。
  4) 保持 -np 1；契约端口/参数其余不变。

六、错误语义（本轮仍有效）
  - 文件缺失 -> 400（"视觉模型文件不存在：..."）
  - 没有 pair -> 409（信息含「视觉模型」，见上轮空 MODEL_DIR 实例验证）
  - 组件缺失 -> 500（带 llama-server.exe 路径）
  - spawn 失败 -> 500（带 vision.log 路径）
  - 排队超时 -> 503（180s，本轮未构造实测）
  - 转发失败且重试后仍失败 -> 502（message 带 vision.log 路径）
  - 无图请求仍走原 nlc 路径（409 未加载模型）
