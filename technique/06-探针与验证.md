# 探针与验证

项目里有 50+ 个探针脚本（`server\probe-*.mjs`），是唯一的回归手段。

## 三类

| 类型 | 需要什么 | 例子 |
|---|---|---|
| 纯接口 | 只要服务在跑 | `probe-sessions`、`probe-workspace-api`、`probe-code-run` |
| 界面 | Edge headless + CDP（9333） | `probe-ui-new`、`probe-start-screen`、`probe-ctx-panel` |
| 真模型 | 会装卸模型、发真对话 | `probe-tools-agent`、`probe-chat-plain`、`probe-second-opinion` |

## 怎么跑

```powershell
# 接口类
node probe-sessions.mjs http://127.0.0.1:8099

# 界面类：先起 headless Edge（Edge 157 起必须带 --no-sandbox，否则 exit 13）
& "${env:ProgramFiles(x86)}\Microsoft\Edge\Application\msedge.exe" --headless=new --no-sandbox `
  --remote-debugging-port=9333 --user-data-dir="$env:TEMP\edge-probe" --window-size=1440,900 `
  "http://127.0.0.1:8099/"
node probe-ui-new.mjs http://127.0.0.1:9333 D:/LocalModels/server/docs/ui-new
```

注意：

- 端口别写死。历史上多个探针硬编码 8098，应用改跑 8099 后它们全废了——现在统一用 `/:80\d\d\//` 正则认页面。
- `$env:ProgramFiles(x86)` 这种写法在 PowerShell 里**取不到值**（会拼出 `C:\Program Files(x86)...` 报「识别为 cmdlet」）。要写 `${env:ProgramFiles(x86)}`。
- 两个界面探针**不要同时跑**：共用一个页面标签，会互相抢 `sessionId`。
- 便携版会自动加载模型，探针里别假设「没有已加载模型」。
- 反过来也成立：**有一批探针默认「模型已加载」**（hero-modes / start-flow / status / ctx-panel / small-features / session-jump / ui-tools / ui-web / auto-title / chat-plain）。驱动已经会先 `POST /api/load`；单独跑某一条时先装模型，否则会看到一片红——2026-10-30 就是这么红了 11 条。
- 判断「红」之前先看服务还在不在：Vulkan device lost 会让进程直接退出（裸跑 node 时没人拉起），后面的探针会以「秒退 + 0 条断言」的形式红，那不是产品问题。
- **headless Edge 要跟着「发起它的进程」活着**（2026-11-14 实测）：Edge 会随起它的工具进程一起被回收，所以「起 Edge → 等 CDP → 跑探针」必须放在**同一条命令**里；写成独立 .ps1 让 `powershell -File` 去起，CDP 往往起不来（`cdp=False`）。
- **Edge 157 上 `--headless=new` 必须配 `--no-sandbox`**，否则进程直接 `exit 13`、9333 不监听，35 条界面探针会整批 `exit 1` / 0 断言——看着像产品全崩，其实是浏览器没起来。
- **界面探针要在干净会话集上跑**：反复补跑会把 `workspace\sessions` 堆成十几条，`small-features`（复制到别人的正文）、`ctx-panel`（上下文余量 100% 告警）、`sidebar-search`（两条同名 `SIDEBAR-ALPHA`）、`ui-tools`（卡片错位）都会假红。补跑前先把 `workspace\sessions` 恢复成真实会话。

## 破坏性探针（小心）

`probe-ui-sessions` 的 `wipe()` 会**删掉服务端所有会话**。曾经因此丢掉 13 条真实对话（`unlink` 不可恢复）。

现在 `wipe()` 会先整份备份到 `docs\session-backups\<时间戳>\` 再删。**跑它之前仍然要确认：这不是生产环境。**

## 怎么判断红了是谁的错

1. **应用缺陷**：换台机器、换个数据也一样错。
2. **探针过期**：界面改版后断言还在找旧元素（`#moreBtn` 早就删了）、硬编码端口/模型名。
3. **环境问题**：缺运行库、虚拟机没 GPU、端口被占。

## 全量巡检（一次跑完 47 个）

```powershell
# 1) 起服务（源码目录即可，界面探针用 Edge 直连端口，不需要启动器）
cd D:\LocalModels\server; node app.mjs
# 2) 起 headless Edge
& "${env:ProgramFiles(x86)}\Microsoft\Edge\Application\msedge.exe" --headless=new --remote-debugging-port=9333 --user-data-dir="$env:TEMP\edge-probe" --window-size=1440,900 "http://127.0.0.1:8099/"
# 3) 跑驱动脚本（逐个跑、单条超时；开跑前自行预加载模型；服务挂了自动拉起并重装模型）
& D:\LocalModels\server\docs\run-full.ps1   # 全量 53 条（固定入口；各轮目录里的副本只作历史）
```

驱动脚本会按 A 接口 → B 界面结构 → C 带对话的界面 → D 真模型 → E 装卸模型 的顺序跑。
日志、截图、三个汇总（首跑 / 复跑 / 二次复跑）都留在同一目录。

跑之前：先备份 `workspace\sessions`；模型会真的装卸，别在你自己正用着的时候跑。

## 探针会过期（这一条比什么都重要）

2026-10-27 的全量巡检首跑 25 绿 / 12 红，最后确认 **11 条是探针过期或环境**，只有 2 条是真问题。
常见的过期方式，改断言前先对号：

| 过期方式 | 例子 | 正确写法 |
|---|---|---|
| 写死模型个数 / 名字 | 「列出全部 4 个模型」，10-25 加了 0.5B 就永远红 | 先 `GET /api/state` 取 `models.length` / `loaded` |
| 依赖某个会话里的旧内容 | 会话搜索里搜 `turtle` | 自己在页面上注入要搜的正文 |
| 界面改版后的旧选择器 | 找 `#moreMenu`（10-22 挪进设置） | 对着 `app.html` 现有 id 重新写 |
| 忘了启动页是新对话 | 刷新后直接找 `#msgs .tool` | 先点 `#recentOpen` 进会话 |
| 开场白页量布局 | 量出 `0/0` | 先进入会话再量 |
| 测试互相污染 | 上一条探针把 `$E=mc^2$` 留在草稿里 | 开场清 `localai.draft.*` |
| 写死阈值 | 第二意见「<15s」，机器慢时 17.6s | 阈值写成「远小于装卸」的量级（<25s），并保留 `swapped=false` 这类结构断言 |
| 探针写死端口/地址 | `probe-model-add.mjs` 不读 argv 里的 CDP，永远连 `127.0.0.1:9333`；在 9335 上跑会 `fetch failed (ECONNREFUSED)`，看起来像「发布包坏了」 | 跑前要么把 Edge 起在探针默认端口，要么先 grep 探针里的 `9333` 确认它认不认参数 |
| 量到装饰层的溢出 | 窄窗断言 `body.scrollWidth <= innerWidth + 2`：`header::before` 是 HUD 扫光伪元素（26% 宽、7s `translateX` 到 480%），会把 `body.scrollWidth` 按相位撑大（实测 850→1126 抖）；`body` 是 overflow:hidden，用户看不见，这条必然假红 | 量「真实 DOM 元素不越界」（`rect.width>0 && rect.right<=innerWidth+2`）+ `scrollTo(9999,0)` 后 `scrollX===0`；或临时 `prefers-reduced-motion: reduce` 关动画。伪元素不在 `querySelectorAll` 里，不会误报 |
