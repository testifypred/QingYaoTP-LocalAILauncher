# 架构

## 进程结构

```
启动本地AI.exe (C# 启动器, 常驻托盘)
  ├─ 自检：VC++ 运行库 / 端口占用 / 磁盘余量
  ├─ 拉起 runtime\node.exe app\app.mjs   →  HTTP 8099（仅 127.0.0.1）
  └─ WebView2 窗口 → 加载 http://127.0.0.1:8099/
```

- 服务挂了（非 0 退出）启动器自动重启；10 分钟内崩两次会切 CPU 后端。
- 关窗口 ≠ 停服务：托盘右键才有「停止服务并退出」。
- 常量：`PORT=8099`、`MODEL_DIR`（`config.ini` 的 `modelDir`，留空则用 `<安装目录>\models`）。

## 两个大文件

| 文件 | 规模 | 职责 |
|---|---|---|
| `app\app.mjs` | ~3900 行 | HTTP 路由、模型生命周期、KV 会话、工具注册表、插件、下载、TTS、代码执行 |
| `app\app.html` | ~5000 行 | 整个界面（无框架、无构建）：布局、会话、工具卡片、设置、首启、外观 |

没有构建步骤是刻意的：改完刷新页面就生效（`app.mjs` 改完要重启 node）。

## KV 缓存复用（性能的地基）

- `state.sequence` / `state.session` 常驻；多轮只解码增量，首字 16.7s → 0.97s。
- 会话指纹 `sessionKeyOf({file, contextSize, thinking, tools, system})`：任何一项变了就重建会话，旧 KV 作废——**这是正确的**，比复用带旧提示的 KV 安全。
- 自动标题为了不打断 KV，单独开 512 上下文生成，不往对话 sequence 里塞 token。
- 代价：改历史（裁剪上下文）会让整段重算；**工具路径每轮都重新 prefill**（工具说明 ~548 token，9B 在这台核显上约 7–8s——这就是「开工具后首字慢」的来源，2026-11-15 实测）。

## 工具调用协议（自己定的一套）

为什么不用库函数：node-llama-cpp 从 jinja 模板探测函数调用语法，探不到时**静默丢弃 `functions`**，模型只能吐原始文本。

现在的链路：

1. 工具是纯数据注册表 `{name, description, params, run}`（`buildToolRegistry`）。
2. 说明书（工具清单 + `<tool_call>` 格式 + 硬规则）拼进 system prompt。
3. 模型输出 `<tool_call>{"name":…,"arguments":{…}}</tool_call>`，`parseToolCalls` 解析（支持未闭合块、坏 JSON 容错）。
4. 逐个执行 → `<tool_response>` 回填 → 再问一次，最多 `TOOL_ROUND_LIMIT`（默认 4，`TOOL_ROUNDS` 可调）。
5. `stripToolCalls` 把调用块从正文里剥掉，用户只看答案。

**流式（2026-11-15 起）**：工具路径也边生成边推正文。做法是 `createToolCallScrubber()`——按 token 累积，遇到 `<tool_call>` 开头就整块扣住（含跨 token 的半个标记），只放行确认不是标记前缀的片段；一轮结束时 `finish()` 放尾巴，未闭合的调用块丢弃。思考段仍走 `reasoning_content`。工具事件照旧实时推卡片。

> 注意：流式解决的是「干等」，不是「慢」。工具模式仍要多付 548 token 预填充，首字实测 ~8s（普通问答 1.5–2s），所以「调用工具」默认关。

## 会话与快照

- 会话：`<MODEL_DIR>\workspace\sessions\<id>.json`，懒建（发第一句才落盘），400ms 防抖，内容没变不抬 `updatedAt`。
- 快照：覆盖写盘**之前**把原文字节存到 `workspace\session-snapshots\<日期>\<id>.<时分秒-毫秒>.json`；单会话留 20 版、保留 30 天；删除会话前也会留一份。
- 回滚 = 用快照再走一次 `writeSession`，所以回滚本身可撤销。
- 搜索：`GET /api/sessions/search?q=` 逐个读会话文件，数标题与正文命中，返回第一条命中附近的片段；界面 250ms 防抖，搜索态下 3 秒轮询只更新缓存、不重绘列表。

## 文档检索（RAG）

零依赖、全本地的一条：**切段 → BM25 → 工具**。

- 索引范围：`workspace` 下 `.md/.markdown/.txt/.log/.rst/.csv`（单文件 ≤1MB、最多 800 个文件、8000 段），跳过 `sessions/`、`session-snapshots/`、`rag/`。
- 切段：空行分段；超长段落按 500 字滑窗。落 `workspace\rag\index.json`，按 size+mtime 增量更新。
- 检索：英文按词、中文按相邻两字（bigram），BM25（k1=1.5,b=0.75），同一文件最多 2 段。
- 工具：`search_documents(query, k)` 走同一个工具注册表与 Agent 循环；检索前自动增量同步，60 秒内不重复扫目录。

## 模型生命周期

`loadModel`：卸载旧模型 → 释放同名预加载 → `createContext` → 建两个 chat wrapper（`noThink` / `think`）→ 探测思考能力 → 可选草稿模型。

默认走 `noThink`（思考模型的空回复问题由它解决）；`thinking:true` 才允许思考。

## 首启与下载

- `workspace\onboarding.json` 记 `done`，未完成则界面弹引导：**硬件体检 → 嗅探本机 → 或下载**。
- 下载器：ModelScope 直链（必须带浏览器 UA，否则 403），跟随 302，写 `\.downloads\*.part` 再 rename。
- 下完自动加载并发第一句，让用户 30 秒内看到结果。
