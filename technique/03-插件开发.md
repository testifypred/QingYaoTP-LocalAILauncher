# 插件开发

插件 = `plugins\` 下的一个 `.mjs` 文件。**保存即生效**，不用重启服务。

目录位置：`<安装目录>\plugins`（源码目录是 `server\plugins`）；可用环境变量 `PLUGIN_DIR` 改。

## 契约

```js
export const name = "disk_space";            // 字母/下划线开头，模型看到的就是它
export const description = "查询各磁盘剩余空间。用户问「还剩多少空间」时使用。";
export const params = {                       // 可选，但建议写：模型靠它填参
  type: "object",
  properties: { letter: { type: "string", description: "盘符，例如 C" } },
  required: [],
};

export async function run(args, ctx) {
  // ctx = { workspace, modelDir, log }
  return { drives: [{ drive: "C:/", freeGB: 165.5 }] };   // 必须能 JSON 化
}
```

## 启用 / 禁用

设置 → 工具 → 插件：每个插件一行，右侧「启用 / 禁用」。禁用只记文件名（`workspace\plugins.json` 的 `disabled` 数组），**文件还在**，删掉名单项或点「启用」就回来。禁用的插件不会被 import、也不会注册成工具——留着一个只用一次的插件又不想让它占系统提示词时用它。

新放进去的插件默认启用；加载失败的在列表里显示原因，不影响其它插件。

三条硬规则：

1. `name` 必须存在且唯一（重名会自动加 `_2`）。
2. 返回值必须 `JSON.stringify` 得出来（模型只能看见文本）。
3. **抛错就是工具失败**：错误信息会原样回填给模型，所以要写人话（「文件不存在」而不是 `ENOENT`）。

## 示例（随包三个）

| 文件 | 作用 | 演示 |
|---|---|---|
| `hello.mjs` | 回显名字与时间 | 最小模板 |
| `disk.mjs` | 各盘剩余空间 | 用 Node 内置 `statfs` |
| `notes.mjs` | 往工作区 `notes.md` 追加/读取便签 | 用 `ctx.workspace` |

## 运行时行为

- **热重载**：`fs.watch` 监听目录，改动后 400ms 防抖重载全部插件；reload 用带时间戳的 `import()` 绕开模块缓存。
- **失败隔离**：单个插件 import 失败只标 `ok:false` 并写日志，不影响其它插件和主流程。
- **同一条链路**：插件工具和内置工具共用 `record()`，所以界面的工具卡片、耗时、journal 完全一致。
- 只有勾选「调用工具」时插件才会出现在系统提示里（`tools:true`）。

## 调试

1. 设置 → 工具 → 插件：看「N 个可用」和失败原因。
2. `POST /api/plugins/reload` 强制重载。
3. 日志在 `logs\app.log`，加载失败会打印 `插件加载失败 <file>: <原因>`。
4. 想单测逻辑，直接 `node -e "import('file:///…/x.mjs').then(m=>console.log(m.run({},{})))"`。

## 安全边界（重要）

插件跑在**主进程**里，权限和程序一致：能读文件、能发网络、能起进程。

- 只放自己信得过的 `.mjs`。
- 没有沙箱、没有超时中断（长任务会卡住工具轮次）。
- 要隔离得另起子进程 + 限权，那是另一个量级的工程。
