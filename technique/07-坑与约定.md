# 坑与约定

这里每一条都真实踩过、并且花了时间。动代码前扫一眼。

## 一、环境类

| 坑 | 现象 | 原因 / 解法 |
|---|---|---|
| **PowerShell 5.1 要 UTF-8 BOM** | 脚本报「Unexpected token」，中文注释变乱码 | 没有 BOM 时按 GBK 读。用编辑器另存为 UTF-8 with BOM，或 `[IO.File]::WriteAllBytes` 补 `EF BB BF` |
| **BOM 会被悄悄剥掉** | 用编辑器/工具链改过 `.ps1`，文件还能「看起来正常」，但在 5.1 里读成 GBK，一堆「Missing closing '}'」 | 改完先看前 3 字节（`[IO.File]::ReadAllBytes` 应为 `EF BB BF`），再用 5.1 的 `[Parser]::ParseFile` 复验。10-30 改 `run-full.ps1`、11-15 改 `build-portable/make-zip` 都中了这一条（**用这个仓库的编辑工具改 .ps1 必丢 BOM**） |
| **`Get-Command node` 是垫片** | 明明 `node -v` 正常，但打包进 `runtime\node.exe` 的只有 **120 字节**，目标机起不来 | 这台机器 PATH 上是 DSH 的 `node.cmd`（设置 `ELECTRON_RUN_AS_NODE`）。要真 `.exe` 且 >1MB；`build-portable.ps1` 已按这个规则筛（11-15） |
| **PowerShell 变量名大小写不敏感** | 新脚本里参数 `-Out` 与局部变量 `$out` 撞名，赋值被 `[string]` 的类型约束转成字符串，`CopyTo` 报「Cannot find an overload for "CopyTo" and the argument count: "1"」——看起来像 .NET API 用错，其实是变量被改写 | `$Out` / `$out` / `$OUT` 在 PS 里是**同一个变量**。`make-vision-pack.ps1` 就这么踩过：`param([string]$Out)` 与流复制用的 `$out` 撞名 → 改成 `$inStream` / `$outStream` 并加注释。给参数起名时先检查脚本里有没有同名局部变量 |
| **`$env:ProgramFiles(x86)` 取不到值** | 报「无法将 `C:\Program Files(x86)\...` 项识别为 cmdlet」 | 带括号的环境变量名要写 `$` + `{env:ProgramFiles(x86)}`；文档里的旧命令就错在这，已修 |
| **新系统缺 VC++ 运行库** | `spawn git ENOENT`，或进程直接 0xC0000005 | 原生模块加载失败会静默退化去编译。装 `vc_redist.x64.exe` |
| **VMware 的 e1000e 网卡** | VM 一开机就 panic（`E1000PCI: failed to register e1000e device`） | 改用 `ethernet0.virtualDev = "e1000"` |
| **虚拟机里没有 GPU** | 永远是 CPU | SVGA 无 Vulkan 计算设备，结构性问题，别折腾 |
| 端口被别的程序占 | 服务起不来、界面白屏 | 启动器现在会自动改口并写回 `config.ini` |
| **工作区子目录写入被拒（沙箱 ACL）** | 受限模式下 `server\`、`workspace\`、`dist\` 里连建目录都「访问被拒绝」，`icacls /reset` 也失败 | 那些目录的 ACL 是 DSH 授权**之前**缓存的旧继承结果，缺沙箱包 SID `S-1-4-377911666-448210640` 的写授权（`D:\LocalModels` 根 / `logs` / `mmproj` / `tools` 有）。切会话到**完全权限**即可；要长期用受限模式就得把继承重新下发一次（别手工逐条改 ACL） |
| **headless Edge 157 `exit 13`** | `--headless=new` 起来就退，9333 不监听，界面探针整批 0 断言 | 加 `--no-sandbox`；且 Edge 会随起它的进程被回收，「起 Edge + 跑探针」必须同一条命令（详见 `06-探针与验证`） |
| **headless Edge 158 不接受命令行 URL（2026-11-20 新坑）** | Edge 升级到 **158.0.4370.33** 后，`msedge --headless=new --no-sandbox --remote-debugging-port=9333 <url>` 立刻退出（exit code 空），stderr：`Multiple targets are not supported in headless mode`，9333 不监听 | **不要把 URL 作为命令行参数**：只带 `--headless=new --no-sandbox --remote-debugging-port=9333 --user-data-dir=<新目录> --window-size=1440,900` 启动（会自动开一个 about:blank / file 页），再用 CDP `Page.navigate` 导航到目标页。**没有这一步，界面探针会「CDP 里没有 8099 的页面」/ E 段 skip** |

## 二、模型与推理

| 坑 | 现象 | 解法 |
|---|---|---|
| `build:"auto"` 静默编译 | 报 `spawn git ENOENT`，和真实原因无关 | 一律 `build:"never"` |
| 思考模型空回复 | 生成的正文是空的 | 默认走 `noThink` wrapper；自动标题也必须传 |
| 工具调用被 max_tokens 截断 | 原始 `<tool_call>` JSON 漏进正文 | 解析器接受未闭合块，并从正文剔除 |
| 裁剪上下文 | KV 复用失效，整段重算 | 已知代价；要性能就别裁 |
| **工具路径原来不流式**（11-15 已修） | 开工具后要等 19–35s 才蹦出整段回答，终端却很快 | 两个原因叠加：①整轮不流式 ②「调用工具」被开场白默认打开。现在：`createToolCallScrubber` 扣住 `<tool_call>` 后逐段推、工具说明 717→548 token、工具默认关 + 开场白不再自动 `applyHeroMode('agent')`。**修后普通问答 1.5–2s，开工具 ~8s 开始逐字** |
| 开场白默认套 Agent 模式 | 用户从没开过「调用工具」，但每次提问都走工具分支、慢一截 | `showHero()` 里那句 `applyHeroMode('agent', true)` 会勾上复选框并 `saveSettings()`。默认行为不要替用户开昂贵选项 |

## 三、数据与文件

| 坑 | 现象 | 解法 |
|---|---|---|
| **探针 `wipe()` 删库** | 所有会话消失，`unlink` 不可恢复 | 现在删前自动备份到 `docs\session-backups\`；跑之前确认不是生产环境 |
| 快照文件名只到秒 | 同一秒两次写盘互相覆盖 | 时间戳加毫秒 |
| 路径太深 | 解压丢文件、模型加载异常 | 解到 `C:\LocalAI`，别在 `Downloads\xxx\xxx` 里套两层 |
| `data\` 被占用 | 打包时 `Move-Item` 失败 | 打包前彻底停应用（含 WebView2 子进程） |
| **`build-portable.ps1` 重置 dist 的 `config.ini`** | 重打包后本机起来是 **0 模型 / 0 会话** | 打包默认 `modelDir=`（＝`<安装目录>\models`）。本机运行目录要手动填回 `modelDir=D:\LocalModels`；交付 zip 里则是消毒后的空值，两回事 |

## 四、界面与终端

| 坑 | 现象 | 解法 |
|---|---|---|
| `app.html` 里写字面量 `<think>` | 被工具链改写 | 用 `String.fromCharCode(60)` 拼 |
| **启动器是单实例** | 改了 `app.mjs` 后 `Start-Process 启动本地AI.exe` 没有任何效果：它只激活已有实例，**不会重启服务**，于是还以为是「路由没生效」 | 要重启必须先结束启动器进程（`Get-Process 启动本地AI` → Stop-Process）再启动；或者托盘菜单「停止服务并退出」 |
| **顶栏加按钮会挤坏窄窗** | 175% 缩放下窗口只有 ~850 CSS px：按钮文字竖排成「文/件」，最右侧主题键被挤出屏幕 | `.topbar` 必须 `flex-wrap:wrap` + 子项 `flex:none` + 按钮 `white-space:nowrap`；`probe-ui-debug` 在 850px 下断言「不竖排、不横向溢出」 |
| 中文宽度 | TUI 边框逐行歪掉 | 折行/截断/补齐都走同一个 `charWidth()`（CJK 记 2 列） |
| 模型输出带 ESC 序列 | 能把界面刷没 | 上屏前 `stripAnsi()` |
| `.cmd` 里写中文注释 | GBK 控制台当命令执行，满屏报错 | 批处理保持纯 ASCII |
| 面板用全局 `.settingsBody` 选择器切页 | 嗅探/预加载弹窗内容被一起隐藏 | 只切 `#settingsModal .settingsBody` |

## 五、探针

- **不要硬编码端口**。历史上的 `8098` 让多个探针在应用改跑 8099 后全部失效。
- 界面探针共用一个页面标签，**不要并行跑**。
- 断言别假设「默认状态」：语速、模型名、开关都可能被用户改过。
- **界面探针要在干净会话集上跑**：反复补跑会把会话堆成十几条，`small-features` / `ctx-panel` / `sidebar-search` / `ui-tools` 因此假红（复制到别人的正文、上下文 100% 告警、两条同名 `SIDEBAR-ALPHA`）。补跑前先恢复 `workspace\sessions`。
- **分批补跑要各自起 Edge**：每批用同一个 CDP 页面跑完就关，别指望上一批留下的 Edge 还活着（会被回收）。

## 六、约定

1. **日志只追加不回改**：`DeveloperRealtimeLog.md` 按时间流水，改错了另起一笔说明。
   **追加长文件前先核对 read 的 `totalLines` 与返回 `lines.length`**（默认上限 2000 行 / 64KB）；2026-11-22 深夜把截断结果当全文 `write` 回日志 → 截掉 3437 行，最后从 DSH session transcript（`harness\sessions\--D-LocalModels--\<id>\session.v4.jsonl.zstd` 逐帧 zstd 解压）里 write 工具的 `meta.diffs[0].oldText` 恢复（`git diff --numstat` = 253 insertions / 0 deletions）。追加优先用 `edit`（old_string=末尾几行）或 shell `>>`。
2. **`app.html` 改完刷新即可**，`app.mjs` 改完必须重启 node（启动器会自动拉起）。
3. **服务只绑 `127.0.0.1`**，破坏性接口一律要 `x-local-token`。
4. **探针是唯一回归手段**：动完必须跑相关的几个，别靠肉眼。
5. **数字必须可复现**：写性能就要写清机器、模型、上下文。
6. **失败要归因**：文档里写「为什么错」，不只是「错了」。
7. **脚本不写死盘符**（2026-11-15 起）：构建/运维/探针脚本一律「由脚本位置推导 + 参数/环境变量覆盖」。写死 `D:\LocalModels`、`D:\Node.js\node.exe` 这类路径会让别人 clone 下来按 README 跑不动——本轮就是因为这条被指出来才整改的。

## 七、视觉增强包（v1.6.0 拆分后）

主包不再带 `app\llama\`（101.1MB / 53 文件），改发可选的「视觉增强包」zip。下面几条是这一轮踩过 / 定下的：

1. **体积与文件数口径（v1.6.0 终版实测，别和旧口径混用）**：发布目录 **258.5MB / 3447 文件**；拆分前基线 **359.5MB / 3499 文件**（拆完 = 3499 − 53 个 llama 文件 + 1 个新增 `vision-pack.mjs`；**3498 是 v1.4.0 旧口径**，README 进包后 +1）；主包 zip **121.9MB（127,852,310B）/ 3947 条目**（= 3447 文件 + 500 目录项；对照 v1.5.1 = 158.5MB / 4000 条目 → **-36.6MB / -53 条目**）；视觉增强包 zip **36.6MB（38,408,198B）/ 56 条目**（53 个文件 + `vision-pack.json` + 2 个目录项，解压 106,017,053B）。
2. **装 / 卸都会先停视觉 sidecar**：Windows 上 `llama-server.exe` 还在跑时换 exe / 删目录会被占用，所以 install / uninstall 都先 `stopVision()`；**正在看图**（`vision.active > 0`）时直接 409，让用户等请求结束。写脚本 / 探针时别在 sidecar 跑着的时候动安装目录。
3. **老版本升级上来是 `legacy`，开发目录是 `tools`**：来源只看安装目录里有没有 `.vision-pack.json` 标记——`pack` 有标记 / `legacy` 只有文件（≤v1.5.1 升级上来的）/ `tools` 开发目录 `tools\llama.cpp` / `none` 都没有。`uninstallable` 只对「装在安装目标上」的为 true：**开发目录那套 101MB 是仓库资产，界面里不给卸**（点卸载回 409 并说明原因）。
4. **本地包搜索目录 + 文件名规则**：`LOCALAI_VISION_PACK_DIR`（`;` 分隔）优先；否则默认 `<app>\..`（发布包 = 安装目录本身）、`<app>\vision-pack`、**`<app>\..\..`（安装目录的上一级——主包 zip 常和 `dist\` 并排放在这层）**、`<app>\..\..\dist`（开发态 HERE = `server` → 仓库根 / `server\vision-pack` / 仓库上一级 / 仓库上一级的 `dist\`）。**文件名必须匹配 `*vision-pack*.zip`** 才会出现在「检测到本地增强包」里；名字里能解析出 `v1.2.3` 就顺手显示版本。**「上一级」这条是 2026-11-15 发布包冒烟实测补的**：发布包在 `dist\QingYaoTP AILauncher\` 时，原来只看安装目录和它下面的 `dist\`，看不到并排的 `dist\...vision-pack.zip`。
5. **安全口径（装的是要执行的 exe，必须挑剔）**：只接受 `<前缀>llama/**` 与 `<前缀>vision-pack.json` 条目；绝对路径 / 盘符 / `..` → 400 且**一个字节都不落盘**；required 8 件缺一 → 400；每个文件校验 CRC32 与声明大小；先解到同级临时目录再**原子换目录**（失败回滚旧目录）；zip 本身上限 600MB、未压缩总量上限 2GB（防 zip 炸弹）。`vision-pack.json` 的 `bytes` 用实测（106,017,053B），契约示例里的 106004121 是估计值。
6. **界面文案写「约 40MB」，实测 36.6MB**：文案是保守估计（`ggml-vulkan.dll` 42MB 压缩率比预估高），别拿它当断言依据；体积以 `build-report.txt` 为准。
7. **新增文件必须同时补 `build-portable.ps1` 的两处清单（复制 + 自检）**：本轮新增 `server\vision-pack.mjs` 时漏了，第一次终版 zip 的 `app\` 里没有它 → 目标机能装能起界面，但 `app.mjs` 一 import 就崩（本机 dist 不炸是因为源码就在原地）。症状与 `doc-extract.mjs` 那次一模一样。判断方法：`Get-ChildItem` 比 `dist\app\` 与 `server\` 的文件集合，或直接看终版 zip 里有没有 `app/vision-pack.mjs`。
## 八、代码审查 / 修正与终端 TUI（v1.7.0）

1. **审查 / 纠正进行中切模型必 409——这是救命约束，别绕**：代码审查用的是同一份模型权重的**独立小 context**，这时 `POST /api/load` 会把底层权重卸掉换别的 → 原生层卡死（CPU 持续涨、HTTP 全部超时）。2026-11-15 15:41 与 15:52 两次 8099「整体无响应」都是「审查中 + 另一客户端切模型」叠出来的。现在：`review/stream` 与 `fix` 由 `codeJob` **串行锁**跑，期间 `/api/load` 一律 **409**「代码审查/修正正在进行，等它结束再切换模型」；前端「审查模型」下拉**不先调 `/api/load`**，把 model 塞进请求体由后端在锁内切。隔离回归 `concurrency-check.mjs` **7/7**：审查中 `/api/state` 仍 200、`/api/load` 409、两个并发 review 串行完成、空闲后 load 恢复 200。
2. **审查必须两阶段**（先流式思路、再单独要 JSON）：4B 这种小模型一次让「边写分析边给结构化 JSON」经常给不出合法 JSON（要么 JSON 被包在解释里、要么字段缺）。现在第一阶段只让它输出「审查思路」（逐条 `-`，带行号与理由，流式 `delta`），第二阶段在同一 context 里单独问一次 JSON（`phase` 事件先告诉界面「正在整理问题清单…」，再出 `findings`）；服务端还会从文本里兜底抽 ```json 块（抽不到就降级 `issues: []`）。
3. **聊天输入框的真实 id 是 `#q`**（不是 `#input`）：需求/契约里写 `#input` 是笔误，这个代码库的聊天输入框是 `#q`（开场白是 `#heroInput`）。「发回对话」要同时写这两处，否则用户在看开场白时会以为没反应。
4. **TUI 宽度统计必须跳过 ANSI 转义（零宽）**：`strWidth/truncWidth/padWidth` 以前逐字符计数，`ESC[36m` 被算成 4 列 → 彩色行被误截断 / 补白错位（snapshot 里标题右边框对不齐）。现在 ESC 序列按零宽跳过，只有真截断时才补 `reset` 防颜色外溢。**改 TUI 版面先看 `--selftest` 的宽度/CJK/ANSI 几项**。
5. **多行 sys 日志会破坏版面**：`/help`、`/tools` 这类多行输出以前作为**一个** body 项塞进一屏行数组，内嵌换行会跳到 0 列、把下一行顶掉。现在按行铺开（`error` / `tool` 同理），整屏不再错位。
6. **TUI 的 `--json` 必须按原始串解析**：先按空格切词会吃掉 JSON 的引号（本轮实测踩到并修好）。现在 `--json` 之后的整段按 JSON.parse，`--json={...}` 也支持；`key=value` 才走切词 + 类型推断（数字 / true / false / null / 其余字符串）。
7. **`localai tui --hint-test` 还不通**：`localai.mjs` 的参数白名单没放行 `--hint-test`；探针/自检直接用 `node localai-tui.mjs --hint-test "/to"`。交互式 `localai tui` 不受影响。
8. **版本号变了就必须重打包（v1.7.0 / v1.7.1 的教训）**：v1.7.0 当时按要求只改源码、没动 dist，用户装上后「看不到新功能」；后补打 dist + 主包 zip 才解决（v1.7.1 同样补打）。**下次交付前**必须重建并同步 5 个文件（`server\app.mjs`、`server\app.html`、`server\localai-tui.mjs`、`server\localai.mjs`、`server\package.json`）+ `README.md` + 新探针。别在交付时才想起来——`probe-version` 与「设置 → 关于」会对版本，但 dist 里跑的还是旧代码。
9. **Phi-4-mini 在 Vulkan 上做审查会偶发原生层卡死（2026-11-15 全量 r1 实测）**：`probe-code-review-stream` 切到 `Phi-4-mini-instruct-Q4_K_M.gguf` → 就绪 8.7s 后**生成不返回**、`/api/state` 全超时、CPU 持续涨（加载日志 `load_arch_hparams: Phi SWA is currently disabled`）；隔离单跑同一请求 22.3s 能过 = 偶发。**别用 Phi-4-mini 做审查模型**；全量驱动已注入 `PROBE_SKIP_SWITCH=1` 跳过该分支（隔离跑仍 48/48）。防御：review/fix 的生成加 `AbortController` 超时（默认 **300s**，`CODE_JOB_TIMEOUT_MS` 可调，超时发 504 事件）——**对「很慢」有效，对「原生层彻底卡死」发不出定时器，只能重启进程**。
10. **驱动的 `Ensure-Server` 会把「服务活着但卡死」误判成「已退出」**：它只按 `/api/state` 超时判断，r1 时误判后尝试重启，撞上原进程还在 → `EADDRINUSE`（全量日志里能看到）。遇到连续多条探针超时 + 端口占用，先怀疑「服务卡死」而不是「服务没了」：**先看 CPU 是否持续涨、再手工 `GET /api/state` 判活**，必要时用精确命令行杀进程再起（见 `05-打包与部署` 的杀进程写法）。
11. **`done` 之后必须立即 `res.end()`（v1.7.1 修的竞态）**：原来 `done` 发完还要等 `ctx.dispose()` 才结束响应，这期间界面仍按 busy 处理——用户点「一键纠正」会被前端当成「停止」，纠正发不出去。现在 SSE 的 `done` 之后立刻 `res.end()`，dispose 在后台继续。**改 SSE 收尾逻辑时先看这条**。
12. **`res.on('close')` 掐生成 + 前端 abort，才能真省 CPU**：审查/纠正中途关页面或点「停止」，只断前端 fetch 不够——后端要监听 `res.on('close')` 调 `ac.abort()` 把原生层生成停掉（日志「已停止（客户端断开）」）。v1.7.1 起 `review/stream` 与 `fix` 都这么做了；不掐的话 GPU/CPU 还在跑，下一次审查会被串行锁堵住。
13. **模型给的行号不可信 → `snapIssuesToCodeLines`**：实测 9B 会把问题标到**空行**或纯注释行，高亮落上去像 bug。后端在 findings 发出前统一校正：空行/纯注释行在 **±2 行**内吸到**含代码的行**，同距离**先向下**，越界 clamp；两处提示词也要求行号指向含代码行；前端问题卡片额外显示该行原文（空行显示「（空行）」、60 字截断）。**别在前端再自己猜行号**。
14. **Phi-4-mini 前端隐藏、后端仍允许**：v1.7.1 起 `#cwReviewModel` 过滤 `/^Phi-4-mini/i` 并显示 hint（已知会卡死应用，见第 9 条）；但**后端 `pickCodeJobModel` 不拦**——探针 `probe-code-review-stream` 的 D 段要显式切它做模型切换测试（全量里用 `PROBE_SKIP_SWITCH=1` 跳过）。

## 九、代码审查二次验证（v1.8.0：质询 / 他人复审 / 云端复审）

1. **五项必须共用同一把锁**：审查 / 纠正 / 质询 / 他人复审 / 云端复审都走后端 `codeJobLocked`，前端也共用 `cwReviewBusy` 一个 busy。少一处就会出现「质询还在跑、用户又点他人复审」→ 两个流程抢同一份权重 / 同时切模型 → 原生层卡死（第 8 章第 1 条的同款事故）。**`/api/load` 的 409 依赖 `codeJob.busy`，别另开锁变量**。
2. **质询是 stateless，别改成服务端存会话**：服务端每次新建小 context、把最近 4 轮 `history` 逐轮重放后再问——不占主会话 KV、不串会话、探针能确定性复算。代价是每轮重算 prompt（4B 10–30s/轮）。改多轮实现时注意：`history` 只会保留最近 4 轮、question/answer 分别截到 1500/4000 字符。
3. **`compareReviewFindings` 是启发式，口径要一起改**：匹配靠「行距 ≤2 或区间有交集」+「严重度 rank 相同算一致、不同算冲突」；同一处问题两侧标在差 3 行以上会各算一条 `onlyX`。判定优先级：**有冲突 或 正好一方 0 问题** → `contradicts`；否则有未匹配项 → `differs`；全匹配 → `consistent`。改阈值/口径时**必须同步改 `probe-code-review-verify` 的 stats 自洽断言**（`matched=agree+conflicts`、`matched+onlySecond===second`、`matched+onlyPrimary===primary`）。
4. **第二审查员永远不选 Phi-4-mini**：自动挑模型时过滤 `/^Phi-4-mini/i`；显式指定 Phi 直接 **400**（比 review 的「允许指定」更严格，因为复审是自动换模型的场景，用户看不见挑中了谁）。
5. **云端 key 只存 `<程序目录>\data\cloud-review.json`**：不写 `config.ini`（dev 目录没有该文件，`updateConfigFile` 直接跳过）。`GET /api/cloud/config` 只回 `keyMasked`；日志只记 host/模型/字符数/脱敏处数/秒数；`make-zip.ps1` 兜底清 `config.ini` 的 cloud 三键，并**断言交付 zip 里没有 `data/cloud-review*` 条目**。`data\` 本来就被 robocopy `/XD data` 整目录排除。
6. **`confirm` 必须等于当前 host，不能省**：前端每次弹 `#cloudConfirmModal` 让用户确认目标域名，请求体带 `confirm=<host>`；后端 409 `CONFIRM_REQUIRED`。这样即使用户配置被改（或配置来自上次遗留），也不会「静默把代码发到别处」。**别加「记住本次选择」**。
7. **云端只接受 https**（本机回环 127.0.0.1 / localhost / ::1 可用 http）——明文 http 会把 Bearer key 送上网。探针的 stub 必须用 `127.0.0.1`，用域名会 400 `INSECURE_URL`。
8. **上游调用 v1.9.1 起是真流式**（`stream:true`，解析 OpenAI 兼容 SSE，收到 delta 就转发）：`text/event-stream` 的按真流式；返回整段 JSON 的老网关自动兜底按 ~80 字分段（stub/测试仍可只回 JSON）。**重试阶梯要发 `retry` 事件**：第一次尝试可能已经推过 reasoning 增量，重试前让前端清空输出区，否则两次内容会叠在一起；`deltaCount` 也要在重试时清零，避免把「上一次的非流式补发」逻辑误跳过。超时用 `CLOUD_JOB_TIMEOUT_MS`（默认 60000，夹 5000–180000），超时 504；读流中途超时抛 504 而不是 502。
9. **脱敏顺序是契约的一部分**：`sk-…` → `key=value` 形式 → 邮箱 → Windows 绝对路径 → IPv4 → 32+ 位 hex。计数依赖顺序（前面的规则先吃掉，后面的不再重复计数），**改顺序会让探针的 `redactions` 断言变红**；也别把邮箱规则放在 IP 前面以外的顺序随便调。
10. **云端结论要写回 `cwIssues`**：这样「一键纠正 / 单条更改 / 发回对话」对云端结论同样可用；别给云端单独做一套渲染。
11. **推理型云端模型会「吃掉」`max_tokens`（v1.8.1 修复）**：DeepSeek `deepseek-flash` 这类模型先输出 `reasoning_content` 再输出 `content`；`max_tokens=1200` 时 reasoning 能把预算用光 → `finish_reason="length"`、`content=""`。只读 `content` 的代码会误判成「不是 OpenAI 兼容响应」。现在：默认发 `thinking:{type:"disabled"}`；不认这个参数 → 去掉重发；还空 → 放大 max_tokens 重发；再空 → reasoning 兜底当正文（`meta.usedReasoningFallback`），**别把 reasoning 直接当结论扔掉**。`502 CLOUD_EMPTY` 只在两边都空时出现。要隐藏只在 UI 层隐藏，别在后端加拦截。
12. **导出 / 三方对照的行数要取「编辑器行数」与「三份快照最大行号」的较大者**（v1.9.0）：`normalizeReviewIssues` 会把行号 clamp 到 `1..lineCount`，如果用户刚切到很短的文件、快照是长文件的结论，所有行号会被压成 1 → 三方对照全糊成一行（探针 E6 实测踩过）。前端口径在 `cwLineCountForExport()`。
13. **快照必须带代码指纹（`cwCodeSig()`）**：导出/三方对照只用「与当前编辑器同一份代码」的快照，改过代码的旧结论自动失效——否则用户改完代码再导出，会把上一版的问题当成本版结论。
14. **界面探针切过会话的，收尾必须还原 `localStorage['localai.lastSession']`**（v1.9.0 踩过）：`probe-code-review-export` 的 E 段 `loadSession(临时会话)` 后又 DELETEs 掉，但 lastSession 指针没还原 → 后面的 `probe-start-flow` / `probe-small-features` / `probe-start-screen` 因为「上次对话」丢失全假红（6/8、1 fail、11/12）。修法：开跑前记旧值、收尾写回并 reload。**新增任何会 enter/leave 会话的界面探针都要守这条。**



## 十、GitHub 发布与 CI（2026-11-17/18）

1. **本机不要用 HTTPS 推 GitHub**：Watt Toolkit / Steam++ 的「GitHub 加速」把 `github.com`、`github.io`、`raw.githubusercontent.com` 等写进 hosts 指向 `127.0.0.1`，自己监听 443 → **`git push` 稳定 403**（clone/pull 有时能过，所以很容易误判成权限问题）。用 **SSH over 443**：
   ```text
   # ~/.ssh/config
   Host github.com
     HostName ssh.github.com
     Port 443
     User git
   ```
   remote：`git@github.com:<owner>/<repo>.git`；`ssh -T git@github.com` 应回 `Hi <owner>! You've successfully authenticated`。副作用要知道：加速器没开时 GitHub Pages / raw 图片会全打不开。
2. **push 403 还有第二个来源：Windows 凭据管理器里的旧账号**。`cmdkey /list | findstr github` 看缓存的是哪个用户；换账号前先 `cmdkey /delete:LegacyGeneric:target=git:https://github.com`，否则 GCM 会一直用旧身份、报 `Permission ... denied`（403）。
3. **远端自动 `Initial commit` → 首推要 `--force`**：GitHub 建仓时勾了 Add README 就会有一个无关历史的提交，直接 push 会被拒；仓库刚建、只有一个自动 README，`--force` 覆盖无损失。
4. **Actions 的 `shell: powershell` 步骤脚本只许 ASCII**：GitHub 把步骤脚本写成 UTF-8 **无 BOM**，Windows PowerShell 5.1 按 ANSI 解码 → 中文吃掉引号 → `Unexpected token` / 字符串未闭合，步骤直接失败。要中文输出就换 `shell: pwsh`；要在 CI 里做 PS 5.1 语法检查，就让 pwsh 起 `powershell.exe` 子进程跑纯 ASCII 脚本（现有 `ci.yml` 就这么做，并在注释里写明原因）。**本地复现**：把步骤脚本存成无 BOM 的 UTF-8，用 `powershell -File` 跑一遍。
5. **CI 只做「确定性检查」，不跑真模型探针**：Runner 没有模型、也没有 Windows GUI 探针环境，所以 `ci.yml` 只查 JS/PS 语法、版本三处一致、仓库卫生（模型/发布包/运行数据不许入库）、README 同源。**真回归仍是本地 63 条 / 1,224 断言**，别把 CI 绿当成回归绿。
6. **提交身份分两层**：推送认证（SSH key 在哪个账号）≠ 提交作者（`git config user.name/email`）。本仓库仓库级设成 `QingyaoTestifypred <testifypred@users.noreply.github.com>`，全局仍是另一个号；**历史不改写**——改写会让所有 SHA 变化，文档里引用的提交号全部失效。
7. **`dist/` 永远不进 git**：交付 zip 靠 Release 附件手动上传；`make-zip.ps1` 的产物在 `.gitignore` 里，别 `git add -A` 误扫进去（122MB）。


## 主页面流式渲染（2026-11-22 输出优化）

1. **不要每帧 `innerHTML = renderMarkdown(整段)` + 全量 KaTeX**：6000 字单帧 14.3–16.8ms（旧做法），越答越卡；改用 `createStreamView` 做**块级增量**（同一口径 0.37–0.48ms/帧）。改流式渲染先跑 `probe-stream-render`。
2. **块切分规则**：空行结束段落；代码围栏以闭合的三个反引号结束；独立 `$$...$$` 公式块以闭合 `$$` 结束；未闭合的尾巴只做**行内 Markdown、不跑 KaTeX**，`finish()` 整体再渲染一次（最终结果与旧版一致）。
3. **rAF 合帧 + 滚动合并**：`schedulePaint` 用 `requestAnimationFrame`；`scroll()` 也只在下一次 rAF 写 `scrollTop`，否则每个 token 都强制 layout。
4. **KaTeX 只在块完成 / 结束时跑**：流式中途不 typeset，每块只 typeset 一次；这是「看着不卡」的关键。
5. **首字税 chip**：本机 4B 实测 工具开 ≈7s、思考开 ≈15s、都关 ≈1.5s（服务端同接口）；输入区上方常显，`updateModeChip()` 在勾选变化 / 开局模式 / 收尾时调用。
6. **Agent / 推理模式改一次性**：`applyHeroMode` 设 `modeOneShot=true`，`doSend` 收尾恢复持久设置；**不要**再在 `applyHeroMode` 里 `saveSettings()`，否则一次点击会永久打开工具。
7. **极简流式**：设置 → 生成 的 `streamLite`，生成中 `textContent = 全文`，`finish()` 再套 Markdown；老机器/长回答可选。
8. **工具说明就是预填充税**：10 个工具描述每个字都要 prefill；瘦身到 ~400 字后 tools 首字仍 ~5.5s，别再写长描述；改完跑 `probe-tools*` 与 `probe-stream-render`。


## 模型加载与内存（2026-11-22：useMmap:false）

1. **Windows Vulkan 上不要用默认 mmap**：这台机器 `supportsMmap=true` 但 `gpuSupportsMmap=false`；node-llama-cpp 的 `useMmap:"auto"` 仍会给 CPU 侧开 mmap，GPU offload 时权重**双份**（文件映射 + 核显共享内存）。20B/12GB 实测：私有 11.8GB + GPU 12.6GB → 可用内存归零、加载 48.6s。
2. **三处加载都要显式 `useMmap:false`**：主模型 `loadModel`、预加载常驻 `preloadModel`、草稿模型。漏一处就会在该路径复现双份。
3. **收益**：20B 加载 48.6s → 14.0s、可用内存 0 → 8.1GB、生成 13.7 tok/s；4B 15.3 tok/s；20B 全 offload 独立基准 15.7 tok/s（ctx 4096）。
4. **卸载后的“诡异 20GB”是备用缓存**：12GB gguf 的页留在 Windows standby（约 11.8GB）+ 系统占用；进程私有已回 0.2GB、GPU 1.7GB。任务管理器看「已缓存」，可被自动回收；要立刻清用 RAMMap Empty Standby List。
5. **别乱调 batch/flash**：batchSize 512 最好（1024/2048 的 ttft 反而略差）；flashAttention 开/关在这台机器无显著差异（KV 量化路径已是 auto）。
6. **部分 offload 不如全 offload**：20 层 9.76 tok/s vs 25 层 15.69；核显上把层留在 CPU 只会拖慢。要省内存就整份 CPU+mmap（3.5 tok/s），要快要全 offload + useMmap:false。


## 代码审查面板滚动（2026-11-22）

1. **流式回调里不要无条件 `scrollTop = scrollHeight`**：审查思路逐 token 追加，无条件跟随会让用户完全无法上滚（用户报的 bug）。只在「距底 < 80px」时跟随。

## 启动器 /health 看门狗（2026-11-24）

1. **位置**：`server\launcher\Launcher.cs`。启动器是 node 的父进程 → 做进程级外部看门狗（前端只能报错，救不了卡死的进程）。
