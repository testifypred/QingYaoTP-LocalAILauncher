# 调试工具（Debugging Tool）

给「本地 AI 出问题了」准备的一层：**独立程序 + 一个诊断接口 + 一个调试页面**。
设计原则和主程序一致：零依赖、只在本机、失败要归因到人话。

## 三个入口

| 入口 | 是什么 | 什么时候用 |
|---|---|---|
| 顶栏 **Debug** 按钮 / 设置 → 工具 →「打开调试窗口…」 | 主程序拉起独立进程 `localai-debug.mjs --ui`，用 Edge 应用模式开一个窗口 | 程序还活着，但行为不对（没回答、后端是 CPU、内存吃紧） |
| `localai-debug.cmd`（程序目录里双击） | 独立程序的命令行版：文本报告 | **程序已经起不来**的时候——它能给出本机诊断（端口、日志、崩溃记录、config） |
| `GET /debug` | 同一个调试页面（也可以直接在浏览器里开） | 排查前端问题、给别人看截图 |

`localai-debug.mjs` 是独立进程，和主程序不共享内存：`--json` 给脚本/探针用，`--logs app|crash` 打印日志尾部。

## 检查项（`GET /api/diag`）

一次返回 `checks[]`，每项 `{id, level: ok|warn|error, title, detail, fix}`。
`fix` 是可以直接照做的处置建议——这是这套东西的重点，不是「报错了」而是「怎么办」。

| 维度 | 检查什么 |
|---|---|
| 服务 | 端口、pid、运行时长、并发数（进行中会挡住切模型） |
| 版本 | `v1.0.0` + git 短哈希 / 打包时间 + 是否有未提交改动 |
| 运行库 | `msvcp140.dll`（缺了 llama 原生模块直接加载不了） |
| 系统 | 内存总量/可用（<2GB 报错）、磁盘余量（<2GB 报错）、核数 |
| 后端 | Vulkan 还是 CPU；最近 10 分钟崩溃次数（≥2 会切 CPU） |
| 模型 | 库里有几个 .gguf、当前加载的文件还在不在、上下文/层数、KV 缓存 token 数 |
| 数据 | 会话数/大小/损坏文件、快照、备份开关、RAG 索引 |
| 插件 | 可用数、加载失败的文件与原因 |
| 一致性 | 源码与 `dist\LocalAI\app\` 的 app.mjs / app.html / doc-extract.mjs 哈希是否一致 |

> 「崩溃记录」和「发布包一致性」这两项是这套工具的私货：前者解释「为什么突然变慢了」（切 CPU 了），
> 后者防止「改完忘了同步发布包」——这两类问题以前只能靠人记。

## 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/debug` | 调试页面（debug.html） |
| GET | `/api/diag` | 诊断快照（上面那张表的内容） |
| GET | `/api/diag/logs?which=app\|crash&lines=200` | 日志尾部；**自动识别 UTF-8 / UTF-16**（PowerShell 重定向写的是 UTF-16） |
| POST | `/api/diag/clear-crash` | 清空 `vulkan-crash.log`（需令牌）：确认稳定后恢复 Vulkan |
| POST | `/api/debug/open` | 拉起独立调试程序开窗（需令牌） |

## 页面上的三个修复动作

- **清空崩溃记录**：下次启动重新尝试 Vulkan；
- **重建文档索引**：RAG 索引坏了/文件大批变动时用；
- **卸载模型**：内存吃紧时立刻释放（之后要重新加载才能问答）。

## 怎么扩

1. 在 `app.mjs` 的 `buildDiag()` 里 `add(id, level, title, detail, fix)` 加一项；
2. 需要新数据就顺手加到返回体的 `server/model/system/paths` 里；
3. 加断言到 `probe-debug.mjs`（接口）与 `probe-ui-debug.mjs`（界面）。

注意：`buildDiag()` 每次调用都会扫会话目录、跑 3 次哈希，属于**按需**接口（页面 5 秒轮询一次，够用）；
真要高频采集，应该拆成「轻量心跳」和「完整体检」两个接口。

## 图标：两套身份，别混

| 身份 | 记号 | 源文件 | 用在哪 |
|---|---|---|---|
| **软件本体「本地 AI」** | `∫ + AI`（不定积分） | `icon-app.svg`；16/24 用 `icon-app-small.svg`（只画 ∫） | `localai.ico` → 启动器 exe / 托盘 / 任务栏 / 窗口标题栏；界面左上角模型按钮的迷你标记 |
| **调试工具** | `∂ + AI + ?`（偏导 + 问号） | `icon-debug.svg` | `debug-icon-64.png` → `/debug-icon.png`，调试页 favicon（调试窗口的标题栏就是它） |

> 这两套曾经被我合成一套（把 `∫` 改成 `∂`），用户当场看出不对——本体是不定积分，`∂` 属于调试工具。改图标前先确认「改的是哪一个身份」。

尺寸分档（16px 塞三个元素必糊）：16/24 → 小稿；32 以上 → 完整稿。`docs\resize-icon.ps1` 按映射缩放，`make-ico.mjs` 打包。
换设计就改对应 SVG 再走一遍：

```powershell
# 1) 渲染 512 源图（Edge 截图必须带 --virtual-time-budget，否则 0 字节）
#    本体：icon-app-512.png / icon-app-small-512.png；调试：icon-debug-512.png
# 2) 缩放 + 打包
& powershell -File D:\LocalModels\server\docs\resize-icon.ps1
node D:\LocalModels\server\make-ico.mjs
# 3) 重编译启动器（exe 的图标是编译时烧进去的，不重编译不会变）
```

**历史稿留在 `server\icons\`**：`original-white.ico`（白底 ∫+AI 原版）、`current-black.ico`、`debug-partial.png`，别删——换图标时先看一眼再决定要不要回退。

启动器用 `/win32icon:localai.ico` 编译（`build-portable.ps1` 第 156 行），所以**换图标要重编译启动器**；
调试工具图标不用编译，它只是 `debug-icon-64.png` 这个静态文件（`GET /debug-icon.png` 直接读它）。
