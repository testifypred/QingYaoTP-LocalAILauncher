# 调试工具（Debugging Tool）

> 产品名：QingYaoTP AILauncher（本地 AI）；调试窗口标题 `Debugging Tool · QingYaoTP AILauncher`。
> v2（2026-11-10）：检查项 17 → **23**，新增诊断历史 / 导出诊断包 / 打开目录，CLI 多四个用法。

给「本地 AI 出问题了」准备的一层：**独立程序 + 一个诊断接口 + 一个调试页面**。
设计原则和主程序一致：零依赖、只在本机、失败要归因到人话。

## 三个入口

| 入口 | 是什么 | 什么时候用 |
|---|---|---|
| 顶栏 **Debug** 按钮 / 设置 → 工具 →「打开调试窗口…」 | 主程序拉起独立进程 **`DebugTool.exe`**（WebView2 窗口，自带 `debug.ico`，任务栏图标清晰）；没有 exe 时回退 `localai-debug.mjs --ui`（Edge 应用模式） | 程序还活着，但行为不对（没回答、后端是 CPU、内存吃紧） |
| `localai-debug.cmd`（程序目录里双击） | 独立程序的命令行版：文本报告 | **程序已经起不来**的时候——它能给出本机诊断（端口、日志、崩溃记录、config） |
| `GET /debug` | 同一个调试页面（也可以直接在浏览器里开） | 排查前端问题、给别人看截图 |

`localai-debug.mjs` 是独立进程，和主程序不共享内存：`--json` 给脚本/探针用，`--logs app|crash` 打印日志尾部。

v2 起多了四个用法（都写在 `--help` 里，服务没跑也能用前两个）：

| 参数 | 做什么 |
|---|---|
| `--export [目录]` | 导出诊断包。服务在跑 → 取 `/api/state.localToken` 调 `POST /api/diag/export`，存 `<目录>/qy-diagnostics-<时间戳>.zip`；服务没跑 → 用本机检查 + 本机日志出离线包（有 `diag-zip.mjs` 就是 zip，没有就退化成目录版）。默认当前目录，打印路径与大小 |
| `--open <dir｜logs｜modelDir｜sessions｜workspace>` | 打开目录。有服务走 `/api/diag/open-path`，没服务直接 `explorer.exe`；名字不在白名单 exit 2 |
| `--history [小时=24]` | 打印历史：采样点数、时间窗、最近的变化（`ok → warn/error`）。无服务 exit 2 |
| `--watch [秒=5] [--cycles N]` | 只打「出现变化」的行（新检查项 / level 变化）；`--cycles` 跑 N 轮就退出（探针自测用） |

原有的文本报告 / `--json` / `--ui` / `--logs` 与退出码不变：**0 正常 / 1 有错误（报告里有 error，或导出失败）/ 2 服务没跑或用错参数**。

**DPI（踩过两次）**：清单里写 `PerMonitorV2` 还不够——.NET Framework 的 WinForms 里 `form.DeviceDpi` 会恒为 96。
必须在 `Main` 里显式 `SetProcessDpiAwarenessContext(-4)`，并且**用 `GetDpiForWindow(hwnd)` 算缩放**：
`Graphics.FromHwnd(IntPtr.Zero)` 返回的是系统 DC 的 96 DPI，照它算会把窗口做成 1180 物理像素，
再被系统整体拉伸——表现就是「窗口小、里面糊」。尺寸要在 `form.Load`（句柄已建）里定。

**为什么窗口要单独编译成 exe**：Edge 的 `--app=` 窗口，图标取自网页 favicon，任务栏里会被缩成糊的；
`DebugTool.exe` 用 `/win32icon:debug.ico` 编译，Windows 直接按 16/24/32/48 取对应尺寸，标题栏和任务栏都清晰。
它的 WebView2 用户数据放在 `<程序目录>\data\webview2-debug`，和主界面互不影响。

## 检查项（`GET /api/diag`）

一次返回 `checks[]`，每项 `{id, level: ok|warn|error, title, detail, fix, group, since, changedAt, streak}`。
`fix` 是可以直接照做的处置建议——这是这套东西的重点，不是「报错了」而是「怎么办」。
`since` / `changedAt` 是这一项处于当前 level 的起始时刻与最近一次变化时刻，`streak` 是连续同 level 的观测次数（页面用它算「已持续 N 分钟」，重启后靠历史文件延续、不回零）。

共 **23 项**（未加载模型时）；加载模型后多出 `kv` / `kvquant` 两行（24–25 项，取决于 KV 量化项与有没有索引）。
按 **六组** 分节，顺序固定：服务 → 系统 → 推理 → 数据 → 扩展 → 发布。

| 组 | id | 检查什么 | fix 口径 |
|---|---|---|---|
| 服务 | `server` | 127.0.0.1:端口 / pid / 运行时长 | — |
| 服务 | `bind` | 只绑回环地址（外部机器连不进来） | — |
| 服务 | `busy` | 进行中的对话数（>0 会挡住切模型 / 卸载） | — |
| 服务 | `version` | v1.3.1 + git 短哈希 / 打包时间；有未提交改动会标出来 | — |
| 系统 | `msvcp` | `msvcp140.dll`（缺了 llama 原生模块直接加载不了） | 装随包的 `vc_redist.x64.exe` |
| 系统 | `node` | node 版本 / 平台 / 核数 | — |
| 系统 | `mem` | 内存总量与可用（<2GB error、<5GB warn） | 卸模型或关别的程序 |
| 系统 | `disk` | 模型目录所在盘剩余（<2GB error、<5GB warn） | 清磁盘（下载和会话快照都要写盘） |
| 系统 | `logs` | `app.log` 体积与最后写入：>50MB warn、>200MB error；还没有日志 → ok | 删旧日志（重启会新建；导出只取尾部 500 行） |
| 系统 | `webview2` | WebView2 运行时版本与目录；探测不到 → warn | 装 Evergreen WebView2 Runtime（主界面窗口和调试窗口都靠它） |
| 系统 | `config` | `config.ini` 是否存在；`modelDir`（空 = 便携默认，detail 里写出实际目录）/ `port` / `gpu` / `vkDevices`；`visionModel` / `visionMmproj` 指定了但文件不存在 → error；`port` 与实际监听不一致 → warn；`vkDevices` 序号超出设备数 → warn | 一句一条，末尾提醒「改完要重启应用才生效」 |
| 推理 | `backend` | Vulkan 还是 CPU | 最近崩过 ≥2 次时解释「为什么自己切了 CPU」 |
| 推理 | `vkdevices` | 用哪几块 Vulkan 设备 / 是否指定了设备 | 核显+独显可去「设置 → 显卡」指定独显 |
| 推理 | `crash` | 最近 10 分钟崩溃次数 | 说明「生成中途点停止/关窗口也会触发 device lost」 |
| 推理 | `models` | 模型目录里 .gguf 数量 | 没有模型 → 嗅探或下载一个入门模型 |
| 推理 | `loaded` | 已加载的文件还在不在、上下文、层数 | 文件不见了 → 模型目录被移动/删除，重新加载 |
| 推理 | `kv` | 常驻序列 token 数、KV 复用开关 | 复用关着 → 说明「每轮整段重算，慢但不影响正确性」 |
| 推理 | `kvquant` | **实际生效**类型（读 `LlamaContext.kvCacheKeyType`）与请求值是否一致、回退原因 | 请求 q8_0 实际 f16（后端不支持 flash attention）→ 可试 `KV_QUANT=q4_0` |
| 推理 | `vision` | 8101 sidecar：运行/未运行（未运行写明「发图时自动拉起，首图 6–12s」）、配对（模型 + mmproj）、上下文、闲置秒数、看完图装回秒数；缺 `llama-server.exe` → error；没有可配对 mmproj → warn；上次启动/请求失败 → warn | 缺组件 → 重装发布包或放回 `app\llama`；缺 mmproj → 放 `modelDir\mmproj`；500 → 点「重读」或看 `vision.log` 尾部 |
| 数据 | `sessions` | 会话数 / 总大小 / 损坏文件数 | 有坏文件 → 先备份再删（坏的会被列表跳过） |
| 数据 | `backup` | 会话备份开关、目录、最近成功多久前、间隔；未开启 → warn；上次失败 → warn；开着但还没跑过第一次 → warn | 「设置 → 工具 → 会话备份」指到另一块盘/U 盘 |
| 数据 | `rag` | 可检索文件数 / 段数 | workspace 里还没有可索引文档 |
| 数据 | `ragfresh` | 索引构建时间 vs workspace 最新文档 mtime；索引存在但文档更新了 → warn（**没有索引文件时不产出这一项**，`rag` 那条已覆盖） | 点「重建文档索引」，或等下一次检索的增量同步 |
| 扩展 | `plugins` | 可用数 / 文件数 / 加载失败的文件与原因 | 把失败原因逐条列在 fix 里 |
| 发布 | `dist` | 源码与 `dist\QingYaoTP AILauncher\app\` 的**六份**文件哈希：`app.mjs` / `app.html` / `doc-extract.mjs` / `debug.html` / `localai-debug.mjs` / `diag-zip.mjs` | 改完源码要拷进 dist，否则发布包跑的是旧代码 |

> 「崩溃记录」和「发布包一致性」这两项是这套工具的私货：前者解释「为什么突然变慢了」（切 CPU 了），
> 后者防止「改完忘了同步发布包」——这两类问题以前只能靠人记。
> v2 补的三项也各对应过一次真实故障：`vision`（发图 500 只能翻日志）、`backup`（检查项被空 `catch` 吞掉，从 11-04 起就没出现过）、`config`（写错 `port`/`vkDevices` 只表现为「怎么老是 CPU」）。

## 诊断历史

页面原来只有「此刻」，答不了「20 分钟前为什么变慢」。v2 起每次体检落一行历史：

- 文件：`<程序目录上一级>\logs\diag-history.jsonl` —— 开发目录是 `D:\LocalModels\logs\`，发布包是 `<安装目录>\logs\`（打包本就把 logs 排除，不进交付 zip，所以**发布包的历史从首次启动才开始记**）。
- 一行一次体检（压缩）：`{"t":"ISO","e":0,"w":2,"o":15,"l":{"vision":"w","backup":"o"}}`，`l` = id → level 首字母（o / w / e）。
- 写入节流：**启动后第一次 / 任一检查项 level 变化 / 距上次 ≥10 分钟**，三者之一才写。页面 5 秒轮询一次，不节流一天能写两万行。
- 超过 **500 行**只保留最后 500 行（读的时候也只看尾部 500 行）。
- `since` / `changedAt` / `streak` 的延续：启动时读历史尾部，把每项「当前 level 从什么时候开始」恢复到内存，所以重启后徽标不回零。
- 只读接口 `GET /api/diag/history?hours=24&limit=200` → `{file, exists, total, hours, points[{t,e,w,o,l}], changes[{t,id,title,from,to}]}`；`changes` 只报 ok↔warn↔error 的变化（不报新增/消失），最多 8 条。

## 导出诊断包

用户要交现场，原来只能截图 + 口头描述。`POST /api/diag/export`（要 `x-local-token`；没有 → **403**）返回 `application/zip`，
头 `content-disposition: attachment; filename="qy-diagnostics-YYYYMMDD-HHMMSS.zip"`；生成失败 → 500 + 人话错误。

zip 是**零依赖 store（不压缩）**：`server\diag-zip.mjs` 里的 `zipStore(entries)` 只写「本地文件头 + 数据 + 中央目录 + EOCD」，CRC32 自己算，不装第三方库。
代价是包不压缩，好处是零依赖、几秒出包，Windows 资源管理器 / 7-Zip / `Expand-Archive` 都能直接打开。

| 条目 | 内容 |
|---|---|
| `README.txt` | 包说明 + 隐私提醒（日志里可能有提问片段） |
| `REPORT.txt` | 人话报告：版本 / 系统 / 服务 / 模型 / 资源快照 + 逐项 `[正常 / 警告 / 错误] title — detail → fix`；和页面「复制报告」同一份格式 |
| `diag.json` | `/api/diag` + 实时资源的原始数据 |
| `manifest.json` | 生成时间、版本、汇总计数、每个文件的字节数与 sha256 |
| `logs/app.tail.txt` | `app.log` 尾部 500 行 |
| `logs/crash.log` | 有崩溃记录才放 |
| `logs/vision.tail.txt` | 有视觉日志才放（尾部 200 行） |
| `config.ini.sanitized` | `modelDir` 值替换成 `<MODEL_DIR>`、用户目录替换成 `<HOME>`；没有 config.ini 时写说明 |

实测大小：开发目录 **38 KB** 上下、发布包 **20 KB** 上下（差在日志尾部长度与检查项多少）。
CLI `--export` 走同一套逻辑；服务没跑时用本机检查 + 本机日志出离线包。

## 打开目录

`POST /api/diag/open-path`（要令牌；没有 → 403）。body `{"which": "dir" | "logs" | "modelDir" | "sessions" | "workspace"}`：

- 白名单外 → **400**（错误消息里列出可选值）；目录不存在 → 404；
- 用 `spawn("explorer.exe", [绝对路径], {detached:true})` 打开，返回 `{ok, which, path}`。

页面三个键 `#openDir` / `#openLogs` / `#openModels`；CLI 用 `--open <名字>`，服务没跑时直接 explorer，名字不在白名单 exit 2。

## 实时资源（`GET /api/diag/resources`）

`buildDiag()` 是「完整体检」（扫会话目录 + 6 次哈希，5 秒一次够了）；「实时资源」走另一个**轻量只读接口**，页面每 2 秒轮询：

| 字段 | 内容 |
|---|---|
| `cpu` | `usagePct`（两次 `os.cpus()` delta；**服务刚起第一次为 `null`**）、`cores`、`model` |
| `mem` | `totalGB` / `usedGB` / `freeGB` / `usedPct` |
| `proc` | `pid` / `uptimeSec` / `rssMB` / `heapUsedMB` / `externalMB` |
| `disk` | 模型目录所在盘：`totalGB` / `freeGB`（`statfs` 失败时为 `null`） |
| `model` | 当前模型、上下文、层数、后端、**`kvQuant`（q8_0/f16）**、KV 复用、常驻 token、并发数 |
| `crash` | 近 10 分钟崩溃次数 |

页面表现：右侧第一张卡「实时资源」= CPU/内存百分比条（≥70% 黄、≥90% 红）+ 进程/磁盘/模型/KV 量化 + 60 点 canvas sparkline（CPU 青、内存 紫、70% 黄虚线），只看可见标签页。CPU 首采 `null` 时显示「—」并 1.1 秒后自动补采。

对应探针：`probe-debug`（接口，**54** 条断言）与 `probe-ui-debug`（页面，**33** 条断言；两轮实测都走品牌图标分支，`loaded` 空但 `selected` 有值时也走品牌分支，「没加载也没选中」的回退分支是 31 条）。

## 页面上的三个修复动作

- **清空崩溃记录**：下次启动重新尝试 Vulkan；
- **重建文档索引**：RAG 索引坏了/文件大批变动时用；
- **卸载模型**：内存吃紧时立刻释放（之后要重新加载才能问答）。

（v2 起同一区还多了三个「打开目录」键：程序目录 / 日志目录 / 模型目录。）

## 怎么扩

1. 在 `app.mjs` 的 `buildDiag()` 里 `add(id, level, title, detail, fix)` 加一项；
2. **去 `DIAG_GROUP` 登记分组**——忘了登记会落到「其他」，页面按六组分节时就地看不见；
3. 需要新数据就顺手加到返回体的 `server/model/system/paths` 里；
4. 加断言到 `probe-debug.mjs`（接口，至少断言这个 id 存在、`since/changedAt/streak` 形状对）与 `probe-ui-debug.mjs`（界面）；
5. id 一旦上线就**别改名**：诊断历史按 id 存 level，改名等于把这项的历史清零。

注意：`buildDiag()` 每次调用都会扫会话目录、跑 6 次哈希，属于**按需**接口（页面 5 秒轮询一次，够用）；
真要高频采集，用轻量接口 `/api/diag/resources`（2 秒轮询、只读、不扫盘）——「完整体检」和「轻量心跳」已经分开。

## 图标：两套身份，别混

| 身份 | 记号 | 源文件 | 用在哪 |
|---|---|---|---|
| **软件本体「本地 AI」** | `∫ + AI`（不定积分） | `icon-app.svg`；16/24 用 `icon-app-small.svg`（只画 ∫） | `localai.ico` → 启动器 exe / 托盘 / 任务栏 / 窗口标题栏；界面左上角模型按钮的迷你标记 |
| **调试工具** | `∂ + AI + ?`（偏导 + 问号） | `icon-debug.svg`（16 用 `icon-debug-small.svg` 只画 ∂；24–48 用 `icon-debug-mid.svg`） | `debug.ico` → 编进 **`DebugTool.exe`**（任务栏/标题栏）；同时 `debug-icon-64.png` 与 `debug.ico` 作为网页 favicon |

尺寸分档（16px 塞三个元素必糊）：16/24 → 小稿；32 以上 → 完整稿。`docs\resize-icon.ps1` 按映射缩放，`make-ico.mjs` 打包。

```powershell
# 1) 渲染 512 源图（Edge 截图必须带 --virtual-time-budget，否则 0 字节）
#    本体：icon-app-512.png / icon-app-small-512.png
#    调试：icon-debug-512.png / icon-debug-mid-512.png / icon-debug-small-512.png
# 2) 缩放 + 打包（本体用 resize-icon.ps1，调试用 resize-debug-icon.ps1）
& powershell -File D:\LocalModels\server\docs\resize-icon.ps1

& powershell -File D:\LocalModels\server\docs\resize-debug-icon.ps1
node D:\LocalModels\server\make-ico.mjs D:\LocalModels\server\icon-parts-debug D:\LocalModels\server\debug.ico
# 3) 重编译两个 exe（图标是编译时烧进去的，不重编译不会变）
#    启动器 → localai.ico；调试工具 → debug.ico
```

**历史稿留在 `server\icons\`**：`original-white.ico`（白底 ∫+AI 原版）、`current-black.ico`、`debug-partial.png`，别删——换图标时先看一眼再决定要不要回退。
