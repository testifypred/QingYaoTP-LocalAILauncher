# HTTP 接口

服务只绑 `127.0.0.1:8099`，默认给界面用；外部程序也可以直接调。

## 鉴权

- 多数接口**不需要**令牌（本地回环 + 同源策略足够）。
- 破坏性或烧 CPU 的接口需要 `x-local-token`，值从 `GET /api/state` 的 `localToken` 取：
  `/api/shutdown`、`/api/run`、`/api/terminal/open`、`/api/download/*`、`/api/sessions/<id>/restore`、**`/api/vision/pack/install`、`/api/vision/pack/uninstall`**（v1.6.0，会往程序目录写/删 exe）、**`/api/code/review/stream`、`/api/code/fix`、`/api/tool`**（v1.7.0：会烧模型 / 真执行软件工具）。
- 别的网页拿不到这个令牌（同源策略 + 自定义头需要 CORS 预检），所以它可以挡住「随便一个网页就能关你的服务」。

## 对话（OpenAI 兼容）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/v1/models` | 模型清单 |
| POST | `/v1/chat/completions` | 主对话入口；`stream` 支持 SSE |

请求体在 OpenAI 基础上多了三个自有字段：

```json
{
  "messages": [{"role": "user", "content": "现在几点"}],
  "stream": true,
  "max_tokens": 512,
  "temperature": 0.7,
  "tools": true,        // 开启工具循环（时间/计算/文件/联网/跑代码/插件）
  "web": true,          // 开联网工具（隐含 tools）
  "thinking": false      // 走「允许思考」的模板
}
```

流式事件：标准 `data: {…choices[].delta.content}`，另外工具执行会推一条 `delta.tool = {name,args,result,ms}`，最后一个 chunk 带 `usage` 与 `metrics`。

## 代码工作区（v1.2.0，v1.7.0 审查/修正改流式）

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/code/capture` | `{files:[{name,content}]}` 1–20 段 → 落到 `workspace\code\`，同名自动 `-2`，返回 `{ok,dir:"code",saved:[{name,path,bytes}]}`；缺 files/空内容 400、单文件 >20 万字符或合计 >40 万字符 413 |
| POST | `/api/code/review` | **老的非流式接口（保留做兜底，v1.7.0 起前端只在流式接口 404 时用它）**：`{code,lang?,file?,intent?,max_tokens?}` → 独立小上下文审查代码，返回 `{ok,review,seconds,model,contextSize,maxTokens}`；空 code 400、>2 万字符 413、无模型/模型正忙 409 |
| POST | `/api/code/review/stream` | **v1.7.0 流式审查（SSE，需令牌）**：`{code(≤20000 字), lang?, file?, intent?, model?, max_tokens?(128–2000，默认 1200)}` → `200 text/event-stream`，事件 `meta → delta* →（可选 phase）→ findings → done`（失败发 `error`）。`meta={model,modelFile,contextSize,switchedModel,startedAt}`；`delta={text}` 是**审查思路**逐段；`phase={phase:"findings"}` = 思路讲完、正在整理问题清单；`findings={summary,issues:[{line,endLine,severity:error|warn|info,title,detail,fix}],lineCount}`（行号已 clamp 到 1..lineCount）；`done={seconds,model}`。校验：**403** 无令牌、**400** 缺 code、**413** code > 20000 字、**404** 指定模型不存在、**409** 没加载模型 / 模型忙 |
| POST | `/api/code/fix` | **v1.7.0 流式修正（SSE，需令牌）**：`{code(≤20000), lang?, file?, intent?, model?, issues?:[{line,endLine,severity,title,detail,fix}], scope?:"all"\|"single", max_tokens?(256–3000，默认 1800)}` → 事件 `meta → delta* → result → done`；`result={code:"<修正后完整代码>", changes:[{start,end}], added, removed, lineCount, coarse}`（`changes` 是**新代码**里的改动行区间、1 起始闭区间，UI 据此高亮）。校验同 review/stream（403/400/413/404/409） |

- 代码文件的增删改查**不新增接口**：复用上面的 `/api/workspace/*`，目录固定 `code/`。
- **老接口**（`/api/code/review`）用固定 system prompt（## 结论 / ## 主要问题 / ## 改进建议 / ## 风险与边界），`temperature=0.2`、`maxTokens` 默认 900（128–1600）。**新流式接口**：第一阶段 prompt 只要求「审查思路」（`temperature=0.2`，不许输出 JSON / 代码围栏），第二阶段只要 JSON（`temperature=0.1`、`maxTokens` 700）；`fix` 用 `temperature=0.15`、默认 `maxTokens` 1800。三条路径上下文都按 8192 → 4096 → 2048 回退，**不碰主会话 KV 缓存**（单开 context，用完 dispose）。
- 界面：顶栏「代码」→ 代码工作区（左侧文件列表、标签页、CodeMirror、运行输出、右侧审查面板）。v1.7.0 起：新建文件可选语言、审查可指定模型、审查流式思维链、问题行高亮、一键纠正 / 单条更改、改动行高亮、发回对话、高亮色自定义（设置 → 代码）。
- **并发互斥（v1.7.0 硬约束）**：审查 / 修正进行中 `POST /api/load` **一律 409**「代码审查/修正正在进行，等它结束再切换模型」——审查用同一份权重的独立小 context，这时切模型会把底层权重卸掉、原生层卡死（2026-11-15 15:41 / 15:52 两次 8099 整体无响应）。`review/stream` 与 `fix` 由 `codeJob` **串行锁**排队，同一时刻只跑一个；前端「审查模型」下拉**不先调 `/api/load`**，把选中 `model` 塞进请求体，由后端在锁内切换（`meta.switchedModel=true` 表示切过）。
- **两阶段审查**：第一阶段只流式输出「审查思路」（`delta`），第二阶段在同一 context 里单独要 JSON（`phase` 事件后出 `findings`）——小模型一次让给两样经常给不出合法 JSON。
- **代码输出模式（2026-11-08）**：默认「写入工作区」——`doSend` 收尾把围栏代码 POST `/api/code/capture`，气泡重渲染成 `.codeWsCard`（打开工作区 / 展开代码），会话条目记 `codeMode:'workspace'` + `codeFiles:[{name,path}]`，刷新后 `renderStoredAssistant` 据此继续折叠；设置 → 生成 可关回对话输出（开关 `localai.codeOutWs`，默认开）。折叠只影响渲染，存档与模型上下文保留完整代码。
- 对话模式下每个代码块一律有「运行 / 复制 / 工作区」三个按钮（`localai.codeRun` 只控制运行按钮显隐）；Agent 模式 +「Agent 模式代码自动收录」（`localai.codeCapture`）只在对话模式下附加「已收录 N 段」提示。

## 看图（视觉 sidecar + 视觉增强包，v1.3.0 / v1.6.0）

底层 llama.cpp 支持 `mtmd`，但 node-llama-cpp 3.22.x 没有视觉 API，所以看图走**独立进程**：官方 `llama-server.exe`（llama.cpp b12144 / v0.9.0-dev Vulkan 构建，53 个文件 / 约 101 MB），按需启动，主服务把带图请求转发过去。

**v1.6.0 起它不再随主包**：`app\llama\` 是可选「视觉增强包」，在 `设置 → 视觉` 安装（实现 `server\vision-pack.mjs`，零依赖自己解 ZIP）；不装时 `POST /api/vision/start` 回 **409** 并指到设置页，界面点图片只弹提示。来源判定看安装目录里的 `.vision-pack.json` 标记：`pack`（包安装）/ `legacy`（≤v1.5.1 升级上来的老文件）/ `tools`（开发态仓库 `tools\llama.cpp`，**不可在这里卸载**）/ `none`。

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/vision/state` | `{running, port:8101, pid, model, mmproj, startedAt, pairs[], selected, context, idleExitSec, mmprojDevice, **pack**}`；`pack = {installed, dir, source, version, files, bytes, uninstallable}`（**v1.6.0 新增**）；未安装时 `note` 追加「视觉增强包未安装…」；`pairs` 由 `modelDir` 顶层 `*.gguf` 与 `modelDir\mmproj\*.gguf`（或顶层含 mmproj 的文件）按文件名族配对 |
| POST | `/api/vision/start` | `{model?,mmproj?}`；启动前会卸载当前文本模型（内存互斥），`/health` 轮询 ≤120s；文件缺失 400、**视觉增强包未安装 409**（message 指到 设置 → 视觉 → 安装视觉增强包，**不是 500**）、超时 504 |
| POST | `/api/vision/stop` | 杀进程树，释放端口 |
| POST | `/v1/chat/completions` | 请求体带 `images:[dataURL...]`（或 content 里的 `image_url`）时转发 sidecar；SSE 原样透传 |

- sidecar 启动参数：`-m <model> --mmproj <mmproj> -c 32768 -ngl 0 -mmdev none --host 127.0.0.1 --port 8101 --jinja --no-webui -np 1`；日志 `logs\vision.log`。
  - **`-ngl 0` 只关文本层，图像编码默认仍走 GPU** → 大图 `ggml_vulkan: device lost` → HTTP 500「failed to process mtmd chunk」。必须加 `-mmdev none`（2026-11-08 修；`VISION_MMPROJ_DEVICE=vulkan0` 可改回 GPU 做对比）。
  - 上下文 / 闲置退出 / 线程：config.ini 的 `visionContext`（默认 32768）、`visionIdleSec`（默认 300 秒，0=不停）、`visionThreads`（默认不传，交给 llama.cpp 自己选）。
  - `/api/vision/state` 额外返回 `context` / `idleExitSec` / `idleAt` / `mmprojDevice`，设置页直接显示。
- **必须带 `chat_template_kwargs:{enable_thinking:false}`**：不带时 Qwen3.5 会把 token 全烧在思考上、`content` 为空（2026-11-07 实测）。
- 模型/mmproj 可在 `config.ini` 用 `visionModel=` / `visionMmproj=` 指定；留空按名字族自动配。
- **同一时间只加载一个重模型**：启动 sidecar 会卸载文本模型；`/api/load` 会先停 sidecar。
- 视觉模型示例：Qwen3.5-9B + `mmproj-F16`（0.86 GiB）、Qwen2.5-VL-7B + mmproj、MiniCPM-V 4.5、Gemma 4 12B。

### 视觉增强包（v1.6.0，可选）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/vision/pack` | **只读，不需要令牌**：`{ok, installed, dir, source, version, sidecar, files, bytes, installedAt, pack, uninstallable, target, running, available[], note}`。`installed` = `<dir>\llama-server.exe` 在不在；`uninstallable` 只对装到安装目标的为 true（开发目录 `tools\llama.cpp` → false）；`available` = 搜索目录里检测到的 `*vision-pack*.zip`，每项 `{path, name, bytes, version}`，**按版本降序** |
| POST | `/api/vision/pack/install` | **需 `x-local-token`（否则 403）**。两种 body：`application/json` 的 `{path, dryRun?}`；或**原始 zip 字节流**（`application/zip` / `octet-stream`，流式落盘，**不吃 4MB 的 `readBody` 上限**，上限 600MB）。成功 200：`{ok, installed, dryRun, stoppedSidecar, install:{version, sidecar, files, bytes, sha256, tookMs, skipped}, pack:{…同 GET}}`。错误：**403** 无令牌；**404** `path` 不存在；**400** 不是有效 ZIP / 缺 required 8 件 / 非法条目（绝对路径、盘符、`..`）/ 不支持的压缩方式 / ZIP64 / 旧目录被占用；**409** 装不上（目录被占用、杀毒拦截）。`dryRun` 只校验、不落盘、不停 sidecar |
| POST | `/api/vision/pack/uninstall` | **需令牌**：`{dryRun?}`。先停 sidecar 再删安装目标（`<安装目录>\app\llama`）；成功 `{ok, installed:false, stoppedSidecar, removedBytes, pack}`；**未安装或来源是开发目录（`tools`）→ 409** |

- **装/卸都会先停视觉 sidecar**（Windows 上换 exe / 删目录会被占用）；**正在看图**（`vision.active > 0`）时 409，等请求结束再来。两条安装路径串行化，两个上传同时到不会互相踩。
- 安全口径：只收 `<前缀>llama/**` 与 `<前缀>vision-pack.json`；绝对路径/盘符/`..` → 400 且**一个字节不落盘**；每个文件校验 CRC32 与声明大小；先解到同级临时目录再**原子换目录**（失败回滚）；装完写标记 `.vision-pack.json`（version / pack / sha256 / installedAt）。
- 检测目录（`available`）：`LOCALAI_VISION_PACK_DIR`（`;` 分隔）优先；默认 `<app>\..`（安装目录本身）、`<app>\vision-pack`、`<app>\..\..`（安装目录的上一级——主包 zip 常在这一层）、`<app>\..\..\dist`（开发态 HERE = `server` → 仓库根 / `server\vision-pack` / 仓库上一级 / 仓库上一级的 `dist\`）；文件名必须匹配 `*vision-pack*.zip`。
- 环境变量：`LOCALAI_LLAMA_DIR`（sidecar 目录 / 安装目标；开发态不设时「实际使用」回落 `tools\llama.cpp`、「安装目标」是 `server\llama`）、`LOCALAI_VISION_PACK_DIR`（找包目录，`;` 分隔）。
- 打包：主包不再带 `app\llama`；`make-vision-pack.ps1` 从 `tools\llama.cpp` 单独出 `dist\QingYaoTP-AILauncher-v<ver>-vision-pack.zip`；`build-portable.ps1 -BundleVision` 可打「离线一体化包」（视觉随主包）。

## 版本与构建

`GET /api/version` 返回：

```json
{
  "version": "1.4.0",
  "commit": "b6a9175",          // 仅当「app.mjs 本身被 git 跟踪」时才有
  "commitAt": "2026-10-30T23:39:33+08:00",
  "builtAt": "",                // 发布包没有 git，退回 app.mjs 的修改时间
  "buildSource": "git",         // git | mtime | unknown
  "dirty": false,               // 工作区有未提交改动时为 true
  "startedAt": "...", "node": "v24.17.0", "pid": 1234, "port": 8099, "dir": "..."
}
```

- 版本号只有一处来源：`app.mjs` 的 `APP_VERSION`；`server\package.json` 的 `version` 必须与它一致（`probe-version` 会查）。
- 发布包是拷贝出来的，即便恰好躺在某个 git 仓库子目录里也**不报那个仓库的哈希**——只认「这份文件被 git 跟踪」，否则退回打包时间。宁可没有哈希，也不要报错的哈希。
- 界面「设置 → 关于」显示同一份数据，并提供「复制版本信息」。
