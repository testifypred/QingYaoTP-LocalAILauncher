# HTTP 接口

服务只绑 `127.0.0.1:8099`，默认给界面用；外部程序也可以直接调。

## 鉴权

- 多数接口**不需要**令牌（本地回环 + 同源策略足够）。
- 破坏性或烧 CPU 的接口需要 `x-local-token`，值从 `GET /api/state` 的 `localToken` 取：
  `/api/shutdown`、`/api/run`、`/api/terminal/open`、`/api/download/*`、`/api/sessions/<id>/restore`。
- 别的网页拿不到这个令牌（同源策略 + 自定义头需要 CORS 预检），所以它可以挡住「随便一个网页就能关你的服务」。

| POST | `/api/unload` | 卸载 |
| POST | `/api/shutdown` | 退出服务（需令牌） |
| POST | `/api/export` | 把会话导出成 Markdown 落盘 |

## 对话（OpenAI 兼容）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/v1/models` | 模型清单 |
| POST | `/v1/chat/completions` | 主对话入口；`stream` 支持 SSE |

请求体在 OpenAI 基础上多了三个自有字段：

```json
{
  "messages": [{"role": "user", "content": "现在几点"}],
  "stream": true,
  "max_tokens": 512,
  "temperature": 0.7,
  "tools": true,        // 开启工具循环（时间/计算/文件/联网/跑代码/插件）
  "web": true,          // 开联网工具（隐含 tools）
  "thinking": false      // 走「允许思考」的模板
}
```

流式事件：标准 `data: {…choices[].delta.content}`，另外工具执行会推一条 `delta.tool = {name,args,result,ms}`，最后一个 chunk 带 `usage` 与 `metrics`。

## 调试工具（Debugging Tool）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/debug` | 调试页面（`debug.html`），也可以用独立程序开窗 |
| GET | `/api/diag` | 诊断快照：`checks[]`（`{id, level: ok\|warn\|error, title, detail, fix}`）+ version/server/model/system/paths + summary |
| GET | `/api/diag/logs?which=app\|crash&lines=200` | 日志尾部（只读最后 128KB，**自动识别 UTF-8 / UTF-16**） |

## 显卡（Vulkan 设备）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/gpus` | 设备清单 `{index,name,vramGB}[]` + `current`（本进程生效）+ `config`（config.ini 里写的）+ `needRestart` + `backend`/`pref` |
| POST | `/api/gpus` | `{devices: "" \| "0" \| "0,1"}` → 写 `config.ini` 的 `vkDevices`；非法/越界 400 |

设备编号就是 `GGML_VK_VISIBLE_DEVICES` 的编号；llama 只在初始化时读一次，**改完必须重启应用**。
界面入口：**设置 → 显卡**（设备名 + 显存 + 自动/指定 + 保存 + 重启提示）。

## 文档检索（RAG）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/rag/status` | 索引了多少文件/段、建索引时间、索引目录 |
| POST | `/api/rag/rebuild` | 全量重建（切段 + 建 BM25 倒排） |
| GET | `/api/rag/search?q=&k=` | 检索，返回 `{file, score, text}`；空 q 400 |
| GET | `/api/tools` | 当前注册的工具（名字/说明/参数名），只读 |

索引在 `workspace\rag\index.json`，只收 `.md/.markdown/.txt/.log/.rst/.csv`（单文件 ≤ 1MB、最多 800 个、最多 8000 段）。
检索前会自动做一次增量同步（按 size+mtime，60 秒内不重复扫目录）；工具 `search_documents` 与界面共用同一份实现。

## 会话备份（镜像到别的位置）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/backup` | 配置 + 上次结果 + 是否同盘 + 会话数 |
| POST | `/api/backup` | `{enabled, dir, keepDays?, intervalMin?}`；目录不合法/不可写当场 400 |
| POST | `/api/backup/run` | 立即备份一次（没配目录 400、正在跑 409） |
| GET | `/api/backup/drives` | 本机盘符与剩余空间（给「选磁盘…」用） |
| GET | `/api/backup/sessions` | 备份里有哪些会话（标题/条数/备份时间/本机是否也有） |
| POST | `/api/backup/restore` | `{id}` 用备份覆盖本机那份（需令牌；走 writeSession，覆盖前先留历史版本） |

落盘布局：`<dir>\sessions\<id>.json`（镜像，只拷变化的）+ `<dir>\daily\<yyyy-mm-dd>\`（当日快照，保留 `keepDays` 天）+ `<dir>\backup.json`（清单，含每个会话的 size/mtime）。
源里没有、备份里有的会话**不会删**。写盘后 15 秒自动排一次，另有 `intervalMin`（默认 30 分钟）的定时检查。
`/api/preload/clear` 会返回 `cleared: [{file, sizeGB}]`——界面的「已取消，释放 X GB」按它逐条报，不再靠页面快照做差集。

## 工作区

`/api/workspace/list`、`read`、`save`、`rename`、`delete`、`upload`——全部做越界校验，`../` 一律 400。

## 代码工作区（v1.2.0）

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/code/capture` | `{files:[{name,content}]}` 1–20 段 → 落到 `workspace\code\`，同名自动 `-2`，返回 `{ok,dir:"code",saved:[{name,path,bytes}]}`；缺 files/空内容 400、单文件 >20 万字符或合计 >40 万字符 413 |
| POST | `/api/code/review` | `{code,lang?,file?,intent?,max_tokens?}` → 独立小上下文审查代码，返回 `{ok,review,seconds,model,contextSize,maxTokens}`；空 code 400、>2 万字符 413、无模型/模型正忙 409 |

- 代码文件的增删改查**不新增接口**：复用上面的 `/api/workspace/*`，目录固定 `code/`。
- 审查用固定 system prompt（## 结论 / ## 主要问题 / ## 改进建议 / ## 风险与边界），`temperature=0.2`，`maxTokens` 默认 900（128–1600）；上下文按 8192 → 4096 → 2048 依次回退（小上下文模型也不至于 500）；**不碰主会话 KV 缓存**（单开 context，用完 dispose）。
- 界面：顶栏「代码」→ 代码工作区（左侧文件列表、标签页、CodeMirror、运行输出、右侧审查面板）；Agent 模式（勾「调用工具」）下助手回复里的围栏代码块会自动 `capture` 进 `code/`，聊天里留一条「已收录 N 段代码」+ 打开入口；设置 → 生成 有「Agent 模式代码自动收录」开关（localStorage `localai.codeCapture`）。

## 版本与构建

`GET /api/version` 返回：

```json
{
  "version": "1.2.0",
  "commit": "b6a9175",          // 仅当「app.mjs 本身被 git 跟踪」时才有
  "commitAt": "2026-10-30T23:39:33+08:00",
  "builtAt": "",                // 发布包没有 git，退回 app.mjs 的修改时间
  "buildSource": "git",         // git | mtime | unknown
  "dirty": false,               // 工作区有未提交改动时为 true
  "startedAt": "...", "node": "v24.17.0", "pid": 1234, "port": 8099, "dir": "..."
}
```

- 版本号只有一处来源：`app.mjs` 的 `APP_VERSION`；`server\package.json` 的 `version` 必须与它一致（`probe-version` 会查）。
- 发布包是拷贝出来的，即便恰好躺在某个 git 仓库子目录里也**不报那个仓库的哈希**——只认「这份文件被 git 跟踪」，否则退回打包时间。宁可没有哈希，也不要报错的哈希。
- 界面「设置 → 关于」显示同一份数据，并提供「复制版本信息」。

## 错误格式

统一 `{ "error": { "message": "人话" } }`，HTTP 状态如实反映：400 参数、403 令牌、404 不存在、409 冲突、413 太大、500 内部错误。
## 首次启动「自动检查用户配置」（v1.1.0）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/sysinfo` | 硬件体检 + 推荐：CPU/核数/内存、GPU（名称+显存，CIM 查）、Vulkan 可用性、VC++ 运行库、磁盘、已有模型；返回 7 条 `checks[]` 与 `recommend{tier, model, contextSize, kvQuant, gpu, reason, notes}` |
| POST | `/api/firstrun/apply` | 按建议写 `config.ini`（仅发布包；开发目录跳过）+ 标记 onboarding done + 推荐模型已在本地则立即按推荐上下文加载 |

推荐逻辑在 `server\config-recommend.mjs`（纯函数，可被探针直接 import 单测）：<10GB（或 <16GB 且可用<6GB）→ 0.5B/4K；<16GB → 0.5B/8K；<24GB → 0.5B（Q8）/8K；≥24GB → 已有 7B/8B/4B 优先、16K。KV 量化默认 q8_0；Vulkan 不可用则 gpu=cpu。
