# 模型与后端

## 模型目录

`config.ini` 的 `modelDir`；留空则用 `<安装目录>\models`。当前机器是 `D:\LocalModels`（VM 里是 `C:\LocalModels`）。

支持：单文件 `.gguf`、分片（`-00001-of-00003` 只认首片）、Ollama 的 `sha256-*` blob（靠文件头 `GGUF` 魔数识别，不看后缀）。

## 下载通道

`/api/download/catalog` 里三档都来自 ModelScope 官方仓库 `Qwen/Qwen2.5-0.5B-Instruct-GGUF`：

| 档位 | 体积 | 取舍 |
|---|---|---|
| Q2_K | 396MB | 最小最快，质量略降 |
| **Q4_K_M** | **469MB** | 默认推荐 |
| Q8_0 | 644MB | 更准，解码更慢 |

要点：

- **必须带浏览器 UA**。ModelScope 对默认 Node UA 直接 403（连 Range 请求也 403）。
- 会 302 到 CDN，必须手动跟随（最多 6 跳）。
- 先写 `\.downloads\<file>.part`，完成后 rename，避免半个文件被当成模型。
- 手动通道接受任意 http(s) 直链，文件名强制 `.gguf` 结尾 + 字符集清洗。

## 后端：`gpu`

`config.ini` 的 `gpu=auto|cpu|vulkan`（启动器透传成 `LOCALAI_GPU`）。

| 值 | 行为 |
|---|---|
| `auto` | 先试 Vulkan，失败退 CPU |
| `vulkan` | 只用 Vulkan |
| `cpu` | 直接 CPU，跳过尝试 |

关键实现：`getLlama({ gpu, build: "never" })`。

**为什么必须有 `build:"never"`**：默认的 `auto` 在找不到预编译包时会**悄悄去编译 llama.cpp**，于是报 `spawn git ENOENT`——和真实原因（原生模块加载失败）毫无关系。虚拟机上踩过一次，浪费了一整轮。

## 全新系统的三个前置

1. **VC++ 运行库**（`msvcp140.dll`）——缺了模型根本加载不了。启动器会检测并引导安装随包的 `vc_redist.x64.exe`。
2. **WebView2 运行时**——缺了自动回退浏览器窗口（不影响功能）。
3. **磁盘 ≥ 2GB**——启动器会提醒。

## 虚拟机里为什么一定是 CPU

VMware 给的是 SVGA 虚拟显卡，没有 Vulkan 计算设备，枚举不到设备 → 必然回退 CPU。这不是软件问题，是虚拟化限制；要用 GPU 得 PCIe 直通（Workstation 不支持）。

实测：4 vCPU 跑 Qwen2.5-0.5B Q4 约 **16.4 tok/s**，内存 3.4GB —— 正好证明「没有显卡的办公机也能用」。
