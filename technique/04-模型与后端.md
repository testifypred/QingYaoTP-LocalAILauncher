# 模型与后端

## 模型目录

`config.ini` 的 `modelDir`；留空则用 `<安装目录>\models`。当前机器是 `D:\LocalModels`（VM 里是 `C:\LocalModels`）。

支持：单文件 `.gguf`、分片（`-00001-of-00003` 只认首片）、Ollama 的 `sha256-*` blob（靠文件头 `GGUF` 魔数识别，不看后缀）。

## 下载通道

`/api/download/catalog` 里三档都来自 ModelScope 官方仓库 `Qwen/Qwen2.5-0.5B-Instruct-GGUF`：

| 档位 | 体积 | 取舍 |
|---|---|---|
| Q2_K | 396MB | 最小最快，质量略降 |
| **Q4_K_M** | **469MB** | 默认推荐 |
| Q8_0 | 644MB | 更准，解码更慢 |
| Qwen2.5-1.5B Q4_K_M | 1.12GB | 更聪明；8GB 机器也跑得动（老笔记本甜点档，2026-11-03 加） |

要点：

- **必须带浏览器 UA**。ModelScope 对默认 Node UA 直接 403（连 Range 请求也 403）。
- 会 302 到 CDN，必须手动跟随（最多 6 跳）。
- 先写 `\.downloads\<file>.part`，完成后 rename，避免半个文件被当成模型。
- 手动通道接受任意 http(s) 直链，文件名强制 `.gguf` 结尾 + 字符集清洗。

## 后端：`gpu`

`config.ini` 的 `gpu=auto|cpu|vulkan`（启动器透传成 `LOCALAI_GPU`）。

| 值 | 行为 |
|---|---|
| `auto` | 先试 Vulkan，失败退 CPU |
| `vulkan` | 只用 Vulkan |
| `cpu` | 直接 CPU，跳过尝试 |

关键实现：`getLlama({ gpu, build: "never" })`。

## 显卡选择：`vkDevices`（2026-11-04 新增）

`config.ini` 的 `vkDevices=`（例 `0`、`0,1`；空 = 全部设备）→ 启动器设 `GGML_VK_VISIBLE_DEVICES`（开发模式由 `app.mjs` 启动段自己读 config）。

- 界面：**设置 → 显卡**——列出 llama 报出的设备（名称/显存）+「自动 / 设备 N」单选 + 保存。保存只写 config.ini，**重启生效**。
- 为什么需要：核显+独显的机器上 llama.cpp 默认取枚举里的第一块，常常是核显（老笔记本实测 RX640 没干活，跑在 UHD 620 上）。
- 排查：`GET /api/gpus` 看 `devices` 与 `current`；`app.log` 启动行 `Vulkan 设备：0=…（只可见 0）`；`/api/diag` 的「显卡选择」项。
- 边界：设备列表来自 Vulkan 驱动；驱动不暴露独显（老 AMD 驱动）时列表里就没有——先升驱动（RX640 最后一版官方 ≈ Adrenalin 22.6.1 / 30.0.15021.11005）。

**为什么必须有 `build:"never"`**：默认的 `auto` 在找不到预编译包时会**悄悄去编译 llama.cpp**，于是报 `spawn git ENOENT`——和真实原因（原生模块加载失败）毫无关系。虚拟机上踩过一次，浪费了一整轮。

## KV 缓存量化（2026-11-01 起默认开）

KV 缓存是「上下文越长越吃内存」的主因：7B（28 层 / 4 KV 头 / head_dim 128）f16 约 **56KB/token**，16K 就要 0.9GB，128K 要 7.3GB。

现在默认用 **q8_0**（约 28KB/token，内存砍半）。**传参必须用数字**（或大写枚举名）：

```js
createContext({
  contextSize,
  experimentalKvCacheKeyType: 8,      // 8 = Q8_0；别传小写 "q8_0"
  experimentalKvCacheValueType: 8,
  flashAttention: "auto",
})
```

> 坑（2026-11-01 踩过）：传小写 `"q8_0"` 时 `resolveGgmlTypeOption()` 解析不到，**静默回落到 F16 且不报错**——`/api/state` 里写着 q8_0，实际是 f16，内存一点没省。实测 `8` / `"Q8_0"` 有效、`"q8_0"` 无效。**判断是否生效必须看 `LlamaContext.kvCacheKeyType`**（`/api/state.kvQuantActual`、调试页「KV 缓存量化」检查项都读它）。

- **失败自动回退 f16**：后端不支持（量化 KV 需要 flash attention）时只记一行日志，应用照常启动；实际类型以 `kvQuantActual` 为准。
- **关掉**：环境变量 `KV_QUANT=f16` 后重启（精度优先/排障用）；`KV_QUANT=off|0` 同义。
- 预加载（第二意见常驻）的上下文也走同一套。

实测（这台机器 31.4GB 内存、Intel Arc 核显、7B Q4_K_M、**真实 q8_0**）：

| 上下文 | 加载耗时 | 加载后系统可用内存 | node WS |
|---|---|---|---|
| 16K | 12–17s | ≈7.4GB | 9.2GB |
| 64K | ≈11.5s | ≈7.4GB | 9.0GB |
| 128K | ≈10.2s | ≈4.8GB | 12.4GB |

对比 f16 的 128K（可用只剩 0.2GB）：q8_0 大约省 3–4GB，128K 从「勉强」变「紧但可用」。

> 另：**一次性 2 万 token 以上的预填充会让 Vulkan device lost**（f16 / q8_0 都会），这是既有的 Vulkan 局限（已知问题 2），不是量化导致的；日常 16K–64K 没问题。

## 全新系统的三个前置

1. **VC++ 运行库**（`msvcp140.dll`）——缺了模型根本加载不了。启动器会检测并引导安装随包的 `vc_redist.x64.exe`。
2. **WebView2 运行时**——缺了自动回退浏览器窗口（不影响功能）。
3. **磁盘 ≥ 2GB**——启动器会提醒。

## 虚拟机里为什么一定是 CPU

VMware 给的是 SVGA 虚拟显卡，没有 Vulkan 计算设备，枚举不到设备 → 必然回退 CPU。这不是软件问题，是虚拟化限制；要用 GPU 得 PCIe 直通（Workstation 不支持）。

实测：4 vCPU 跑 Qwen2.5-0.5B Q4 约 **16.4 tok/s**，内存 3.4GB —— 正好证明「没有显卡的办公机也能用」。
