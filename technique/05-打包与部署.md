# 打包与部署

## 一条命令

```powershell
cd D:\LocalModels\server
powershell -NoProfile -ExecutionPolicy Bypass -File .\build-portable.ps1
```

产物在 `dist\QingYaoTP AILauncher`（**v1.4.1 实测 359.5MB / 3498 文件**（+`app\package.json`，版本对账用），其中 `app\llama\` 是视觉 sidecar 101MB、`runtime\node.exe` 92,825,416B；起服务后 +2 log + server.pid；另有 `data\` 运行期缓存可删）。

### 可移植性（2026-11-15 整改，别退回去）

脚本里**不写死盘符**，一律「由脚本位置推导 + 参数/环境变量覆盖」：

| 项 | 规则 |
|---|---|
| `$OutDir` | 默认 `Join-Path $Repo 'dist\QingYaoTP AILauncher'`（`$Repo` = 本脚本所在 `server` 的上一级）；**可传任意位置**，只要求目录名是 `QingYaoTP AILauncher` 且不是盘根/用户目录 |
| `-Icon` | 默认 `server\localai.ico` |
| `-NodeExe` | 留空则依次找：`LOCALAI_NODE_EXE` → PATH 上的 node（`.cmd` 垫片自动换同名 `.exe`）→ `%ProgramFiles%\nodejs\node.exe` → 扫 PATH 每个目录的 `node.exe`。**候选必须真 `.exe` 且 >1MB** |
| `csc.exe` | 由 `$env:WINDIR` 推导 Framework64/Framework，两处都试 |

> 教训：这台机器上 `Get-Command node` 命中的是 DSH 的 `node.cmd` 垫片（120 字节），旧逻辑会把 120 字节的废文件打进 `runtime\node.exe`，目标机双击直接起不来。现在按「真 .exe + 体积」筛。
>
> 异地构建实证（2026-11-15）：工作目录 `C:\`、`-OutDir %TEMP%\qytp-portable\dist\QingYaoTP AILauncher`，不带任何绝对路径入参 → exit 0 / 12.0s / 359.5MB / 3498 文件，与仓库内构建逐文件一致。

### 打包后必须自检（2026-11-01 踩过）

一次「成功」的打包可能仍然缺文件——`build-portable.ps1` 只复制它清单里写的东西，**清单漏一项，包里就没有**，而且打包过程不会报错：

| 检查 | 命令 / 判据 |
|---|---|
| 关键文件齐 | `app\` 下必须有：app.mjs、app.html、**doc-extract.mjs**、**config-recommend.mjs**、debug.html、localai-debug.mjs、localai-debug.cmd、debug-icon-64.png；根目录有 localai.ico、`QingYaoTP AILauncher.exe`、DebugTool.exe |
| 源码一致 | 三份文件（app.mjs / app.html / doc-extract.mjs）与 `server\` 的 SHA256 相同 |
| 能起来 | 双击 exe 后 `GET /api/state` 返回 200（缺 doc-extract.mjs 会直接 import 失败） |
| 调试工具 | `DebugTool.exe` 存在；`GET /debug` 200、`GET /debug-icon.png`/`/debug-icon.ico` 200、无令牌 `POST /api/debug/open` 403 |
| 视觉 sidecar | `app\llama\llama-server.exe` 与 `mtmd.dll` 在；启动后 `GET /api/vision/state` 的 `pairs` ≥ 1；漏了它看图会 500 |
| 回归 | `node probe-debug.mjs http://127.0.0.1:8099` 25/25、`probe-rag` 16/16 |

> 教训：`doc-extract.mjs`（RAG 的 docx/pdf 抽取）从 10-29 加进源码后**一直没进打包清单**，10-29 那版是手工拷进去的，所以一直没暴露；2026-11-01 第一次真正重打包，包直接起不来。
>
> **2026-11-01 第二轮实测**：`build-portable.ps1` exit 0 / 19.7s、8 步含「编译调试工具」；新包 258.1MB / 3442 文件；12/12 自检绿（DebugTool.exe 42,496B、三份 SHA256 一致、probe-debug 25/25、probe-rag 16/16）。证据：`server\docs\packaging-2026-11-01\RESULT.md`。

**打包前必须先停应用**，否则 `data\` 被 WebView2 占着会失败：

```powershell
cd "D:\LocalModels\dist\QingYaoTP AILauncher"
Start-Process .\QingYaoTP AILauncher.exe -ArgumentList '--stop' -Wait
```

更狠的情况：启动器进程不退出（已知问题），此时按命令行精确杀：

```powershell
Get-CimInstance Win32_Process -Filter "Name='msedgewebview2.exe' OR Name='启动本地AI.exe'" |
  Where-Object { $_.CommandLine -like '*LocalAI*' } | Stop-Process -Force
```

⚠️ 不要用 `Stop-Process -Name msedgewebview2`，会误杀 DSH 等其它 WebView2 程序。

## 交付 zip（build-portable 之后必做）

`build-portable.ps1` 只构建 `dist\QingYaoTP AILauncher`，**不打 zip**。对外交付的是单文件 zip，用：

```powershell
cd D:\LocalModels\server
powershell -NoProfile -ExecutionPolicy Bypass -File .\make-zip.ps1
```

产出 `dist\QingYaoTP-AILauncher-v<APP_VERSION>.zip`（**v1.4.1 实测：158.5 MB / 3999 条目 / 69.0s / SHA256 C3ED469F…**；v1.4.0 时 35D6B656…、v1.3.1 时 3998 条目、v1.2.0 时 3943）。**版本号由脚本从 `server\app.mjs` 的 `APP_VERSION` 解析**，zip 名与包内根目录名自动跟着走——发版时**不用再改这个脚本**。脚本规则（改之前先读，别退回去）：

- `data\` / `logs\` 只留空目录；`models\` 留空目录（用户放 gguf 的地方）；
- 根目录固定 `QingYaoTP AILauncher-v<APP_VERSION>/`（脚本自动解析，别写死），**所有条目正斜杠 + 带这个前缀**；
- 对**暂存副本**的 `config.ini` 消毒：`modelDir=` / `autoLoad=` / `vkDevices=` / **`visionModel=` / `visionMmproj=`** 清空——交付包里绝不能出现本机绝对路径（dist 运行目录里的 config 保持本机配置，这是两回事）；
- **运行期文件不进包**：暂存副本 `app\` 下的 `.pid` / `.log` / `.tmp` 先删（`server.pid` 会把本机 pid 带出去，目标机首启的单实例判断会被它误导）。

打完自检：

| 检查 | 判据 |
|---|---|
| 条目 | ~3998；所有条目以 `QingYaoTP AILauncher-v1.3.1/` 开头；反斜杠条目 = 0；无 `qytp-zip-` 前缀 |
| 卫生 | 无 `data\` / `logs\` 实际文件；无 `models\workspace`、sessions、discovery.json 之类运行期泄漏 |
| 配置 | 包内 `config.ini` 的 `modelDir=` 为空、有 `visionModel=`/`visionMmproj=` 空行，全文无 `D:\LocalModels` |
| 视觉内核 | 包内 `app/llama/llama-server.exe` 与 `mtmd.dll` 在（约 101MB） |
| 内核 | 包内 `app/app.mjs` 字节数 = `server\app.mjs`；`QingYaoTP AILauncher.exe` = 57,856 B |
| 解压 | 解到空目录后关键文件齐、`runtime\node.exe --check app\app.mjs` 通过 |

> 为什么单列一步：11-01 与 11-04 两轮都出现过「dist 已更新、交付 zip 还是旧的」。2026-11-05 补了 `make-zip.ps1`，才把「zip 由谁打」固定下来。
>
> 改 `.ps1` 用编辑工具后会**丢 BOM**：补回 `EF BB BF`（字节方式）再用 5.1 Parser 复验，否则中文乱码 → 语法错误（11-05 又踩一次）。

## 目录结构（发布包）

```
QingYaoTP AILauncher.exe  启动器（带图标、托盘、守护、自检）
vc_redist.x64.exe         VC++ 运行库（缺它模型加载不了）
config.ini                port / modelDir / autoLoad / contextSize / kvReuse / gpu
plugins\                  插件目录（随包 3 个示例）
DebugTool.exe             调试窗口（WebView2，自带 debug.ico）
app\                      app.mjs、app.html、doc-extract.mjs、debug.html、debug.ico、
                          localai*.mjs、localai-debug.mjs、debug-icon-64.png、vendor、node-llama-cpp
localai.ico               本体图标（桌面快捷方式的 IconLocation 指向它）
runtime\node.exe          随包 Node，目标机不用装
logs\app.log              服务端日志
data\webview2\            界面缓存与 localStorage（删掉=重置界面状态）
使用说明.txt
```

## 命令行工具（随包）

| 文件 | 用途 |
|---|---|
| `app\localai.cmd` | CLI：`localai "问题"`、`models`、`load`、`run`、`--json` |
| `app\localai-tui.cmd` | 全屏终端界面：`localai tui` |
| `app\localai-debug.cmd` | 调试工具命令行版：体检 / `--json` / `--logs`（服务挂了也能用） |

`.cmd` 优先用包内 `..\runtime\node.exe`，源码目录自动回落 PATH 上的 `node`；**内容保持纯 ASCII**（GBK 控制台会把中文注释当命令执行）。

## 分发注意

- 未签名 exe 会被 SmartScreen 拦；**用 U 盘/内网拷没有「来自 Internet」标记，不弹警告**。
- 自签名证书只能喂自己人；要让陌生人也不弹，只有 EV 证书（约 ¥3-4k/年）。
- 模型不随包（4-5GB）。目标机首启会引导下载 470MB 的 0.5B。
