# 打包与部署

## 一条命令

```powershell
cd D:\LocalModels\server
powershell -NoProfile -ExecutionPolicy Bypass -File .\build-portable.ps1
```

产物在 `dist\QingYaoTP AILauncher`（**v1.6.0 实测 258.5MB / 3447 文件**（+`app\package.json` 版本对账用、+`app\README.md` 首启使用说明），**不含 `app\llama\`**、`runtime\node.exe` 92,825,416B；起服务后 +2 log + server.pid；另有 `data\` 运行期缓存可删）。
拆分前的基线是 **359.5MB / 3499 文件**；拆完 **3447 = 3499 − 53 个 llama 文件 + 1 个新增 `app\vision-pack.mjs`**（3498 是 v1.4.0 旧口径，README 进包后 +1，别混用）。

### 三个产物：顺序是 build-portable → make-vision-pack → make-zip

v1.6.0 起视觉 sidecar（101.1MB / 53 文件）从主包拆出去，于是打包从「两步」变「三步」：

| 顺序 | 命令 | 产物 | 说明 |
|---|---|---|---|
| 1 | `build-portable.ps1` | `dist\QingYaoTP AILauncher\` | 便携目录，**默认不带 `app\llama`**；自检会断言它不存在 |
| 2 | `make-vision-pack.ps1` | `dist\QingYaoTP-AILauncher-v<ver>-vision-pack.zip` | 可选「视觉增强包」（约 36.6MB），源是仓库 `tools\llama.cpp`，不读 dist |
| 3 | `make-zip.ps1` | `dist\QingYaoTP-AILauncher-v<ver>.zip` | 对外交付主包（约 122MB），读 dist，并断言 zip 里没有 `app/llama/` 条目 |

- **要「离线一体化包」**（目标机没法单独装增强包）就给第 1 步加 `-BundleVision`：恢复旧行为（视觉随主包），此时不必再发单独的视觉包；`make-zip.ps1` 的断言在这种情况下也要跟着让路（它会因为 dist 里有 `app/llama` 而 exit 1——这是设计上的护栏，别绕）。
- 三个脚本的版本号都从 `server\app.mjs` 的 `APP_VERSION` 解析，发版不用手改脚本。

### 可移植性（2026-11-15 整改，别退回去）

脚本里**不写死盘符**，一律「由脚本位置推导 + 参数/环境变量覆盖」：

| 项 | 规则 |
|---|---|
| `$OutDir` | 默认 `Join-Path $Repo 'dist\QingYaoTP AILauncher'`（`$Repo` = 本脚本所在 `server` 的上一级）；**可传任意位置**，只要求目录名是 `QingYaoTP AILauncher` 且不是盘根/用户目录 |
| `-Icon` | 默认 `server\localai.ico` |
| `-NodeExe` | 留空则依次找：`LOCALAI_NODE_EXE` → PATH 上的 node（`.cmd` 垫片自动换同名 `.exe`）→ `%ProgramFiles%\nodejs\node.exe` → 扫 PATH 每个目录的 `node.exe`。**候选必须真 `.exe` 且 >1MB** |
| `csc.exe` | 由 `$env:WINDIR` 推导 Framework64/Framework，两处都试 |

> 教训：这台机器上 `Get-Command node` 命中的是 DSH 的 `node.cmd` 垫片（120 字节），旧逻辑会把 120 字节的废文件打进 `runtime\node.exe`，目标机双击直接起不来。现在按「真 .exe + 体积」筛。
>
> 异地构建实证（2026-11-15）：工作目录 `C:\`、`-OutDir %TEMP%\qytp-portable\dist\QingYaoTP AILauncher`，不带任何绝对路径入参 → exit 0 / 12.0s / 359.5MB / 3498 文件，与仓库内构建逐文件一致。

### 打包后必须自检（2026-11-01 踩过）

一次「成功」的打包可能仍然缺文件——`build-portable.ps1` 只复制它清单里写的东西，**清单漏一项，包里就没有**，而且打包过程不会报错：

| 检查 | 命令 / 判据 |
|---|---|
| 关键文件齐 | `app\` 下必须有：app.mjs、app.html、**doc-extract.mjs**、**config-recommend.mjs**、**README.md**（首启弹窗读它）、**vision-pack.mjs**（视觉增强包实现，缺了 app.mjs import 直接崩）、debug.html、localai-debug.mjs、localai-debug.cmd、debug-icon-64.png；根目录有 localai.ico、`QingYaoTP AILauncher.exe`、DebugTool.exe |
| 源码一致 | 三份文件（app.mjs / app.html / doc-extract.mjs）与 `server\` 的 SHA256 相同 |
| 能起来 | 双击 exe 后 `GET /api/state` 返回 200（缺 doc-extract.mjs 会直接 import 失败） |
| 调试工具 | `DebugTool.exe` 存在；`GET /debug` 200、`GET /debug-icon.png`/`/debug-icon.ico` 200、无令牌 `POST /api/debug/open` 403 |
| 视觉已拆分 | 主包 **`app\llama\` 不存在**（`build-portable.ps1` 自己断言；加 `-BundleVision` 时才要求 `llama-server.exe` 在） |
| 视觉增强包 | `make-vision-pack.ps1` 自检 required 8 件 + 文件条目数 = 源文件数 + 1；装进 dist 后 `GET /api/vision/state` 的 `pack.installed === true` 且 `pairs` ≥ 1（不装只是看图 409，文本不受影响） |
| 回归 | `node probe-debug.mjs http://127.0.0.1:8099` 25/25、`probe-rag` 16/16、`probe-vision-pack` **110/110**（自带 8199 临时实例） |
| 发布包冒烟 | 终版 dist 实测 **26/26**：版本 1.6.0 / 跑的是 dist / 无 `app\llama` / 未装时 `start`→409 / **自动检测到 dist 里并排放的增强包 zip** / `probe-version` 14/14 + `probe-debug` 54/54 / 一键安装（path）→ source=pack、files=53、bytes=106,017,053、落盘+标记 / `probe-vision-api` 真 9B **27/27**（29s）/ 识图后 sidecar 已停（`server\docs\feature-vision-pack-2026-11-15\release-smoke.txt`） |

> 教训：`doc-extract.mjs`（RAG 的 docx/pdf 抽取）从 10-29 加进源码后**一直没进打包清单**，10-29 那版是手工拷进去的，所以一直没暴露；2026-11-01 第一次真正重打包，包直接起不来。
>
> **同款又踩一次（2026-11-15）**：新增 `server\vision-pack.mjs` 时 `build-portable.ps1` 的两处文件清单都没加 → 第一次终版 zip 的 `app\` 里没有它，目标机 `app.mjs` 的 `import` 直接崩（本机 dist 能跑是因为源码就在）。补进清单后重建：主包 zip 条目 3946 → **3947**、发布目录 3446 → **3447**。**新增文件 = 必须同时补 build-portable 的复制清单 + 自检清单**。
>
> **2026-11-01 第二轮实测**：`build-portable.ps1` exit 0 / 19.7s、8 步含「编译调试工具」；新包 258.1MB / 3442 文件；12/12 自检绿（DebugTool.exe 42,496B、三份 SHA256 一致、probe-debug 25/25、probe-rag 16/16）。证据：`server\docs\packaging-2026-11-01\RESULT.md`。

**打包前必须先停应用**，否则 `data\` 被 WebView2 占着会失败：

```powershell
cd "D:\LocalModels\dist\QingYaoTP AILauncher"
Start-Process .\QingYaoTP AILauncher.exe -ArgumentList '--stop' -Wait
```

更狠的情况：启动器进程不退出（已知问题），此时按命令行精确杀：

```powershell
Get-CimInstance Win32_Process -Filter "Name='msedgewebview2.exe' OR Name='启动本地AI.exe'" |
  Where-Object { $_.CommandLine -like '*LocalAI*' } | Stop-Process -Force
```

⚠️ 不要用 `Stop-Process -Name msedgewebview2`，会误杀 DSH 等其它 WebView2 程序。

## 交付 zip（build-portable 之后必做）

`build-portable.ps1` 只构建 `dist\QingYaoTP AILauncher`，**不打 zip**。对外交付的是单文件 zip，用：

```powershell
cd D:\LocalModels\server
powershell -NoProfile -ExecutionPolicy Bypass -File .\make-zip.ps1
```

产出 `dist\QingYaoTP-AILauncher-v<APP_VERSION>.zip`（**v1.6.0 实测：121.9MB（127,852,310B）/ 3947 条目 / 69.9s / SHA256 `95D46B683DED4515D47272A44717846E018DADD0324C043502181B65720C880B`**，**无 `app/llama/`**；对照 v1.5.1 = 158.5MB / 4000 条目 → **-36.6MB / -53 条目**（−53 个 llama 文件 −1 个目录项 +1 个新增 `app/vision-pack.mjs`）；v1.5.0 时 158.5MB / 4000 条目 / SHA256 4D0271FC…、v1.4.1 时 3999 条目、v1.4.0 时 35D6B656…、v1.2.0 时 3943）。**版本号由脚本从 `server\app.mjs` 的 `APP_VERSION` 解析**，zip 名与包内根目录名自动跟着走——发版时**不用再改这个脚本**。脚本规则（改之前先读，别退回去）：

- `data\` / `logs\` 只留空目录；`models\` 留空目录（用户放 gguf 的地方）；
- 根目录固定 `QingYaoTP AILauncher-v<APP_VERSION>/`（脚本自动解析，别写死），**所有条目正斜杠 + 带这个前缀**；
- 对**暂存副本**的 `config.ini` 消毒：`modelDir=` / `autoLoad=` / `vkDevices=` / **`visionModel=` / `visionMmproj=`** 清空——交付包里绝不能出现本机绝对路径（dist 运行目录里的 config 保持本机配置，这是两回事）；
- **运行期文件不进包**：暂存副本 `app\` 下的 `.pid` / `.log` / `.tmp` 先删（`server.pid` 会把本机 pid 带出去，目标机首启的单实例判断会被它误导）。

打完自检：

| 检查 | 判据 |
|---|---|
| 条目 | v1.6.0 实测 **3947**（= 3447 文件 + 500 目录项；比首次终版 +1 = 补进的 `app/vision-pack.mjs`）；所有条目以 `QingYaoTP AILauncher-v1.6.0/` 开头；反斜杠条目 = 0；无 `qytp-zip-` 前缀 |
| 卫生 | 无 `data\` / `logs\` 实际文件；无 `models\workspace`、sessions、discovery.json 之类运行期泄漏 |
| 配置 | 包内 `config.ini` 的 `modelDir=` 为空、有 `visionModel=`/`visionMmproj=` 空行，全文无 `D:\LocalModels` |
| 视觉内核 | **包内不能有 `app/llama/` 条目**（`make-zip.ps1` 用 ZipFile 逐条断言，robocopy `/XD` 是兜底）；要看图的人另装视觉增强包 |
| 增强包 zip | 存在 `dist\QingYaoTP-AILauncher-v<ver>-vision-pack.zip`（56 条目 / 36.6MB）、内含 `vision-pack.json` + `llama\` 53 文件 |
| 内核 | 包内 `app/app.mjs` 字节数 = `server\app.mjs`；`QingYaoTP AILauncher.exe` = 57,856 B |
| 解压 | 解到空目录后关键文件齐、`runtime\node.exe --check app\app.mjs` 通过 |

> 为什么单列一步：11-01 与 11-04 两轮都出现过「dist 已更新、交付 zip 还是旧的」。2026-11-05 补了 `make-zip.ps1`，才把「zip 由谁打」固定下来。
>
> 改 `.ps1` 用编辑工具后会**丢 BOM**：补回 `EF BB BF`（字节方式）再用 5.1 Parser 复验，否则中文乱码 → 语法错误（11-05 又踩一次）。

## 视觉增强包 zip（make-vision-pack.ps1，v1.6.0 新增）

看图用的 `llama-server` + DLL 单独发一个 zip；主包因此轻了 101.1MB。

```powershell
cd D:\LocalModels\server
powershell -NoProfile -ExecutionPolicy Bypass -File .\make-vision-pack.ps1
#   换源/输出：-Src 'E:\build\llama.cpp'  -Out 'E:\build'
#   版本/构建号：-Version 1.6.0（默认解析 app.mjs）  -Sidecar b12144
```

产物 `dist\QingYaoTP-AILauncher-v<ver>-vision-pack.zip`（**v1.6.0 实测 36.6MB（38,408,198B）/ 56 条目 / 7.6–8.9s**，SHA256 `D7924534B30143F3791D26C143B95656306AE1FFA08D52557EE25D56699A11D3`；**每次重打包 SHA 都会变**——`vision-pack.json` 里带 `createdAt`，别当可复现）：

```
QingYaoTP-AILauncher-v1.6.0-vision-pack/   <- 顶层目录（后端安装时剥掉）
  vision-pack.json                         <- 清单（format/name/version/sidecar/createdAt/files/bytes），UTF-8 无 BOM
  llama/<tools\llama.cpp 的全部 53 个文件>  <- 101.1MB，解压 106,017,053B
```

- **56 条目** = 2 个目录项 + 54 个文件（`vision-pack.json` + 53 个 llama 文件）。
- `vision-pack.json` 实测：`{format:1, name:"QingYaoTP AILauncher 视觉增强包", version:"1.6.0", sidecar:"b12144", createdAt:"2026-11-15T…Z", files:53, bytes:106017053}`（bytes 是实测值；契约示例里的 106004121 是估计值）。
- 脚本自检：required 8 件（`llama-server.exe` / `llama-server-impl.dll` / `llama.dll` / `llama-common.dll` / `ggml.dll` / `ggml-base.dll` / `mtmd.dll` / `libomp.dll`）缺一 `exit 1`；zip 文件条目数 ≠ 源文件数 + 1 也 `exit 1`；源目录不存在直接报错退出。
- 不写死盘符：repo 由脚本位置推导，`-Out` 目录不存在会自动建；版本号默认解析 `app.mjs`。

### 装到用户机器上

1. 设置 → 视觉 → 卡片「安装视觉增强包…」选 zip（前端把**原始字节流** POST 上去，进度按 `upload.onprogress` 走，不受 4MB 请求体上限限制）；
2. 或把 zip 和主包放在一起（**安装目录本身**、安装目录下 `vision-pack\`、**安装目录的上一级**（常见就是 `dist\`，主包 zip 放这层）、上上级的 `dist\` 都行），卡片会列出「检测到本地增强包：…」→ 一键安装（走 JSON `{path}`）；
3. 后端 `POST /api/vision/pack/install`（**x-local-token 必需，否则 403**）→ 停 sidecar → 校验清单/required/路径穿越/CRC32 → 解到临时目录 → 原子换目录 → 写标记 `.vision-pack.json`。装完**不用重启**。
- 搜索目录可用 `LOCALAI_VISION_PACK_DIR`（`;` 分隔）覆盖；只认文件名匹配 `*vision-pack*.zip` 的包。
- 来源判定：有 `.vision-pack.json` 标记 = `pack`；只有文件没标记 = `legacy`（≤v1.5.1 升上来的）；开发目录 `tools\llama.cpp` = `tools`；都没有 = `none`。
- 卸载 `POST /api/vision/pack/uninstall`（令牌）→ 先停 sidecar 再删整个安装目标（`<安装目录>\app\llama`）；开发目录不可卸（409）。
- 两个 zip 一起发：主包给不看图的人，增强包给要看图的人；只发主包时点图片只弹提示，不影响其它功能。

## 命令行工具（随包）

| 文件 | 用途 |
|---|---|
| `app\localai.cmd` | CLI：`localai "问题"`、`models`、`load`、`run`、`--json` |
